# 多 agent 分工

大任务按职责拆给多个 agent。好处：每个 agent 只想自己那一摊，单次请求不会超过 10 分钟的超时线；能并行，更快；各自专注，质量更高。
思考强度不降（降了会影响前后一致的算术和衔接），只在纯机械步骤（改格式、按清单替换）上用低强度。

## 唯一真相：骨架文件

拆开以后最大的风险是各节对不上（时长加起来不对、字幕压在不该压的镜头上、剪切不在小节线上）。所以：

- 先由**总导演**产出 `skeleton.json`，所有时间只在这里定义；
- 其他职责只**引用编号**（`S5`、`bar7`、`M2`），不手写秒数；
- 算术用脚本校验，不靠 agent 目测。

位置一律写成 `"小节:拍"`（从 1 开始，拍可以是小数），结束位置是开区间：

```json
{
  "fps": 24, "bpm": 80, "beatsPerBar": 4, "bars": 15, "dur": 45.0, "cutsOnBars": true,
  "shots": [
    { "id": "S1", "start": "1:1", "end": "2:1", "framing": "高角度主构图", "move": "固定", "why": "…" },
    { "id": "S5", "start": "5:1", "end": "6:1", "noText": true }
  ],
  "subs": [{ "id": "M1", "start": "2:1", "end": "3:3", "text": "…" }],
  "silences": [{ "start": "10:1", "end": "10:2" }],
  "nativeMove": "S5", "signature": "S5"
}
```

校验：`python3 ~/.claude/skills/style-studio/scripts/check_skeleton.py skeleton.json`。它查：小节算出的总长 = `dur` 且是整数帧；镜头首尾相接不重叠不留空；`cutsOnBars` 时每个剪切在小节线上（有意例外标 `offBarOk`）；字幕停留 ≥ max(1.8 s, 字数 ÷ 4.5 + 1.5 s)；字幕不压在 `noText` 镜头上；静默在片长内；`nativeMove` / `signature` 指向存在的镜头。

画面各职责改同一个项目时，每人只改自己的文件（`bg.js`、`cel.js`、`fx.js`、`post.js`……），避免互相覆盖；并行改代码时用独立 worktree。

## 风格帧与迭代：先粗后细，按帧并行

2026-11-04《最后一碗面》3 张风格帧 + 1 张设定图用了 3 个多小时：77% 的时间在等模型回复（每个 agent 来回 40–100 次、看图 10–40 次），渲染只占 4%；窗里像落日的雪堆、读不懂的 S5 却一直留到第 4 轮。慢在流程，不在机器。

- **先粗后细**：先出只有剪影和主色的小样（720p），只查「一眼读得懂吗」，用户点头后再上细节。构图和读图问题在小样阶段解决，不带进细修轮。
- **按帧拆文件、按帧并行**：每张风格帧的道具和合成放各自的文件（如 `s5.js`），几张同时做，谁做完谁先送评，不设全员关卡。
- **限时**：一个 agent 一轮最多约 8 次渲染；平时看 720p 小图，最后才看原尺寸；到点交回现状和没解决的问题。
- **先修读不懂的**：评委意见分「读不懂 / 方向错」和「细节」，每帧每轮只修前 3–5 条；读不懂的没解决前不碰细节。
- **见好就给用户看**：风格帧阶段要的是风格成立、方向确认，不追奖级打磨；自动修正最多两轮，之后不管分数先给用户看。

## 写进工作流脚本的规矩

- 依赖用 `pipeline()`：骨架确定后，五个分节各自写完就进入下一步，不互相等。只有场记合成这种需要全部结果的步骤才用 `parallel()` 当关卡。
- 每个 agent 只交回文件路径和短字段，正文写进文件；单次 Write/Edit 不超过约 2500 个汉字。
- **每次启动工作流，同时在后台跑看门狗**（`run_in_background`）：`python3 ~/.claude/skills/style-studio/scripts/watch_agents.py <工作流 transcript 目录>`。有 agent 超时重试或久等无回复，它会立刻退出报警，不要等用户来问。工作流正常结束后用 TaskStop 停掉它。
- 修正步骤也要拆：一个 agent 只修一个职责范围内的问题，不要把十几条问题和整篇长文一起交给一个 agent。
- 一个工作流同时最多跑 8 个 agent，多出来的排队，等前面有人交回才开工（2026-11-05 实测：派 10 个，后两个晚开工 15–20 分钟）。一波最多派 8 个；关键路径上的放在数组前面。
- 一个 agent 只管一个镜头、一件事。2026-11-05 一个 agent 包两个镜头（又摆手型又改连贯）时，动笔前一次想了 10 分钟以上被掐断，拆成单镜头后就没再卡。
- `~/.claude/settings.json` 的 `env.API_TIMEOUT_MS` 已调到 1800000（30 分钟，下次启动生效），这只是兜底，拆分和看门狗才是主要手段。
