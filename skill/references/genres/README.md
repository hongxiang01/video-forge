# 类型卡（genres）

用户原话（2026-11-05）："不同视频的类型和题材都需要考虑……有的可能一分钟就够了，有的可能需要三分钟更好""不是说 skill 不一样，应该他们那个校验逻辑、规范之类的不一样，然后可能提示词也会不一样"。

所以：**入口和流程只有一个（SKILL.md），每种类型 / 时长档有一张类型卡**，卡里写这一类自己的时长预算、结构、视觉和声音规范、校验逻辑（含可脚本测的阈值）和提示词模板。

| 科普讲解 | 3–5 分钟（3–4 章） | [explainer-mid.md](explainer-mid.md) |
| 科普讲解 | 8 分钟以上 | [explainer-long.md](explainer-long.md) |

| 叙事动画 | 30–60 秒微短片 / 2–5 分钟短片 | [narrative-short.md](narrative-short.md) |

不在表里的类型：按 `review-standards.md` 末尾「新类型」的做法和用户一起定核心问题，做完后照这些卡的 9 个小节补一张新卡。

## 每张卡的 9 个小节，在流程里分别给谁用

| 小节 | 用在哪一步 |
|---|---|
| 1 定位与核心问题 | 追问：和用户对齐"观众看完应该怎样" |
| 2 时长与画幅 | 追问：给用户选时长档；写稿：字数 / 句数预算；分镜：镜头数和平均镜头时长 |
| 3 结构模板 | 追问"结构"时给用户选 |
| 4 视觉规范、5 声音规范 | 风格卡、分镜、构建 agent 的约束 |
| 6 校验逻辑 | 和用户一起定「评审标准卡」时的默认检查项（在 `review-standards.md` 通用项和类型项之上叠加）；评委逐条判 |
| 7 提示词模板 | 写稿 / 分镜 / 构建 agent / 评委的提示词起点，按项目填占位符 |
| 8 参考作品 | 每卡 ≤3 个，只学拆出来的做法，不照搬（用户：参考太多会失去方向、变平庸） |
| 9 常见坑 | 开工前过一遍 |

## 用户自己的习惯优先于卡里的默认

卡里的画幅、字幕建议按平台通行做法写，和用户的固定做法冲突时**以用户为准**，并在追问时确认：
- 用户发抖音的做法是**横版 16:9、画面不加字、文案放标题和描述**（memory：douyin-video-publishing）。好几张卡（科普短档、口播、MV、特效、广告）默认推荐竖屏或歌词/字幕上屏，用到时先问清，再按回答取舍。
- 卡里标【经验】/【推】/"待验证"的数字没有可靠出处，做完一条片后按发布数据和复盘调整，并在卡里改掉标注。

## 编号

各卡新增的检查项编号：科普短 KS*、中 KM*、长 KL*、口播 KT*，叙事 D10–D21，氛围 A10–A19，MV M10–M17，特效 F10–F19，广告 P11–P18，微缩 S11–S20。引用 `review-standards.md` 里已有的编号（G*、K1–K13、D1–D7 等）时用原编号。以后新增编号前先在这里查重。
