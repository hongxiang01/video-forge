# 类型卡：知识口播

> 口播 = **一个人在对观众说话**，画面跟着话走。分两种模式：
> - **A. 真人出镜**：用户提供人物素材（绿幕或实拍）。合成侧规则（帧率、抠像、人脸安全区、角标）以 `vendor/video-talkcraft/references/host-footage.md` 为准，这里不重复。
> - **B. 无真人数字口播**：只有声音。画面全部代码绘制；"主讲人"只能是剪影、符号化角色或用户提供的形象图，按铁规矩 7 不演戏（不做口型、不做表情、不做手势）。
> 写稿原则同科普（`narration-guidance.md`）；口播的流程骨架参考 `vendor/video-talkcraft/SKILL.md`（预剪 → 字级时间戳 → 分镜 → 实现 → 机器闸 + 审片）。
> 数字标注：【源】有出处；【推】推算；【经验】经验值，待验证。

## 1. 定位与核心问题

**观众信任这个人，并带走他的一个观点。** 看完能说出"他认为 ___，因为 ___"。
和科普讲解的区别：科普的主角是**被讲的东西**；口播的主角是**讲的人和他的判断**。所以口播的稿子要有第一人称、有立场，画面要服务于"他在说话"，不能盖过他。

## 2. 时长与画幅

| 档 | 时长 | 画幅 | 字数（按下面的语速） | 镜头 / 画面变化 |
|---|---|---|---|---|
| 竖屏短口播 | 45–90 秒 | 9:16 | 200–420 字 | 每 3–5 秒一次画面变化 |
| 横屏中口播 | 3–6 分钟 | 16:9 | 750–1600 字 | 每 4–8 秒一次画面变化；每 30–60 秒换一次版式 |
| 横屏长口播 | 10–20 分钟 | 16:9 | 2500–5300 字 | 同中口播；每章开头换版式 |

- **语速假设**：真人口播 250–300 字/分钟【经验，待用第一条用户素材实测】；TTS 云希原速 5.5 字/秒 = 330 字/分钟，加停顿后约 260 字/分钟（`narration-storyboard.md`）。表里字数按 260 字/分钟【推】。真人素材以实测为准：`voice_trim.py` 预剪后用总字数 ÷ 时长。
- **画面变化**指：人物景别变化（推近 / 切角标）、图形入场、素材切换、版式切换之一。数字为【经验】：真人在画面里说话本身是"动"的，所以可以比纯动画慢；无真人模式按短档 / 中档科普卡的镜头节奏。
- **再钩**：短口播每 15–20 秒一个新观点或反问；中长口播按 K12（每 60–90 秒）。
- **画幅**：talkcraft 默认横屏；抖音 / 视频号主发才做竖屏。横屏发到竖屏平台时，不要直接加黑边，要单独排一版。

## 3. 结构模板

**A. 观点先行（默认推荐）**：0–5 秒直接说结论或反常识判断（"大多数人用 AI 的方式都是错的"）；5–20% 讲"我为什么这么说"（一个亲身经历 / 一个数据）；20–80% 2–3 个论据，每个论据配一个证据画面（截图、图表、地图）；80–95% 回应最常见的反对意见；最后 5% 一句话收回到开头的判断。

**B. 现场带看（Johnny Harris 式）**：人带着观众走进一个地方 / 一张地图。0–10% 人在现场或地图前提出问题；中段人退成角标或画外音，地图 / 素材做主体，每到一个"站"人再回来做一句判断；结尾人回到画面正中，说出自己的结论。

**C. 一口气讲清（小 Lin 说式）**：标题就是"一口气搞清楚 X"。0–8% 用一个生活化比喻把 X 说成观众熟悉的东西；中段按时间线或因果链推进，每章一个比喻 + 一张简单图；结尾讲"这跟你有什么关系"。适合 10 分钟以上的长口播。

## 4. 视觉规范

**模式 A（真人出镜）**
- 人物素材的帧率、时长、比例、抠像：按 `host-footage.md` §1–4，开工前跑 `preflight.py --media-only`。
- **人脸安全区**：任何文字、卡片、字幕及其底板，任何时刻都不进入（`face_bbox.py` 实测，不目测）。主信息面板放在人物对侧。
- **三种人物形态轮换**：半身（人是主角，说观点时）/ 角标（素材是主角，讲证据时）/ 短暂离场（全屏图表、地图）。同一形态 + 同一素材容器不连续超过 3 个镜头（talkcraft 版式轮换规则）。
- **有素材时人物降为角标**，不切走人，也不让人物和素材抢满屏（`host-footage.md` §5）。
- 推近：说重点句时 1.0 → 1.08–1.15 的慢推或一次跳切推近【经验】，一句一次，不连推。

**模式 B（无真人）**
- 主讲人形象三选一：① 剪影 / 轮廓（侧身、坐姿、不动或只做呼吸式缩放）；② 符号角色（一个固定的图形 IP，如一只杯子、一个话筒），像 @我是不白吃 的卡通主持那样贯穿全片；③ 用户提供的形象图，只做位置、大小变化。
- **不做假口型**。用配音音量包络驱动一个"正在说话"的信号（声波条、角色边缘的轻微亮度脉动），振幅和配音同步，误差 ≤1 帧（从 wav 的 RMS 算，不手 K）。
- 画面重心在"他说的东西"上：每一句都有图形响应（K2）；表情包式插图（半佛仙人式）只能用代码画的图形或用户提供的素材，不从网上扒图。
- 主讲人形象占画面 ≤1/4，固定在左下角（竖屏必须左下，右侧是点赞栏；talkcraft `design-language.md` §5）。

**两种模式共用**
- **字幕全程**：口播必须有逐句字幕，素排、整句硬现、不加标点（talkcraft `design-language.md` §5）。横屏 44px、底部 100px；竖屏 48px、底部 350px。
- 字号、安全区：横屏按 G3、G2；竖屏按 `explainer-short.md` §4。
- **证据优先**：说到数据、新闻、产品时，画面上是图表或真实页面截图（用 Remotion 在长截图上"拍"，见 talkcraft ③），不是空泛的氛围图。
- 转场：硬切为主（口播的语言节奏本身就是剪辑点），版式切换用运动承接；不用叠化。

## 5. 声音规范

- **真人录音**：先跑 `voice_trim.py` 预剪（口水词、结巴重说、≥0.7 秒的停顿压到 0.35 秒），dry-run 报告给用户过目后再落盘，再做时间戳（顺序不能换，talkcraft ②-0）。
- **TTS**：一个音色贯穿；给 2–3 个候选让用户试听（《AI 到底该怎么用》复盘：试听 6 个才选定）。语速默认原速，用户嫌慢可 +10% 到 +20%。
- **配乐**：80–100 BPM 的低存在感底乐【经验】，旋律不进人声频段；人声段配乐比人声低 ≥10dB（G4）。观点句、反转句前收音乐 1–2 小节，让话"落地"。真人口播可以大段无音乐。
- **响度**：按 G4。真人录音另查底噪：静音段底噪 ≤ -55 dBFS【经验】。
- **音画同步**（模式 A）：人物嘴型和声音偏差 ≤1 帧（`host-footage.md` §1：差 >1 帧就是口型漂）。

## 6. 校验逻辑

| 编号 | 检查项 | 必须/加分 | 阈值或判据 | 怎么测 |
|---|---|---|---|---|
| KT1 | 有观点 | 必须 | 评委能写出"他认为 ___，因为 ___"；稿子里第一人称判断句 ≥3 句 | 人判 + 稿件统计 |
| KT2 | 开头 5 秒内给出结论或判断 | 必须 | 首个判断句起点 ≤5 秒 | 时间轴 |
| KT3 | 时长与字数 | 必须 | 和需求卡偏差 ≤10%；字数按 §2 表 ±15% | `ffprobe` + 字数统计 |
| KT4 | 人脸安全区（模式 A） | 必须 | 侵入帧数 = 0 | `face_bbox.py` + 抽帧叠框 |
| KT5 | 人物素材体检（模式 A） | 必须 | 素材 fps = 成片 fps；时长差 ≤1 帧；无重复帧 | `preflight.py --media-only`；`motion_check.py --baseline` |
| KT6 | 不演戏（模式 B） | 一票否决 | 没有代码画的口型、表情、手势；"说话信号"与配音 RMS 同步 ≤1 帧 | 抽帧人判；脚本比对 RMS 曲线和信号振幅 |
| KT7 | 画面变化间隔 | 加分 | 竖屏 ≤5 秒、横屏 ≤8 秒必有一次画面变化；列出超标段 | `scene` 检测 + `motion_check.py` |
| KT8 | 版式轮换 | 加分 | 同一人物形态 + 同一素材容器不连续 >3 个镜头 | 读分镜表版式节奏表（talkcraft `preflight.py`） |
| KT9 | 证据画面 | 必须 | 每个数据 / 新闻 / 产品句都有图表或真实截图；代码 mock 的假界面 = 0（无真实对应物时须在分镜表注明） | 逐句对照；人判 |
| KT10 | 字幕 | 必须 | 每句都有字幕，逐字对齐 ±3 帧；不压人脸、不进平台遮挡区 | 字级时间戳对照；抽帧 |
| KT11 | 录音干净（真人） | 必须 | 口水词、结巴重说剩余 0 处；无 >0.7 秒的非设计停顿 | `voice_trim.py --dry-run` 复跑应为空；`silencedetect=n=-40dB:d=0.7` |
| K2 | 每句都有画面响应 | 必须 | 按原条（人物在说话不算响应，至少要有图形 / 景别变化） | 逐句抽帧 |
| K4 | 数字有出处 | 必须 | 按原条 | 对照事实清单 |
| G4 / G7 | 响度、无静止 | 加分 / 必须 | 按原条；模式 B 的 G7 升级为必须 | `ebur128`；`freeze_probe.py` |

## 7. 提示词模板

**写稿**
```
写一条 {时长} 的知识口播稿，由 {主讲人身份} 第一人称讲，主题：{一句话主题}，观众：{谁}。
立场：{主讲人的核心观点一句话}。结构：{观点先行 / 现场带看 / 一口气讲清}（talking-head.md §3）。
预算：{字数} 字（±15%），按 {语速} 字/分钟算；句子要像说话：短句、口语、允许"我觉得""说实话"，不要书面腔。
必须：前 5 秒说出结论或判断；每个论据配一个能上屏的证据（数据来源 / 截图对象 / 地图），在句后标【证据：…】；
回应一个最常见的反对意见；结尾回到开头的判断。数字只用 {事实清单路径}，并换算成可感的尺度。
每句后面标【画面：人物形态（半身/角标/离场）+ 图形或素材】。写完朗读一遍，交第 2 版。
```

**分镜**
```
根据定稿和字级时间戳 {timing.json} 做口播分镜（{横屏/竖屏}，模式 {A 真人 / B 无真人}）。
先写版式节奏表：| 镜 | 人物形态·方位 | 素材容器 | 主卡 |，同一形态 + 同一容器不连续 >3 镜。
每镜写：帧区间、对应句、人物形态、主信息面板位置（人物对侧）、证据素材路径、图形动作、推近与否、音乐收放。
画面变化间隔：竖屏 ≤5 秒、横屏 ≤8 秒。模式 A 先读 face-zone.json，所有文字和卡片避开人脸安全区；
模式 B 主讲人形象固定左下、占画面 ≤1/4，只做呼吸式缩放和音量驱动的说话信号，不做口型。
```

**构建 agent 要点**
- 模式 A：先跑 `preflight.py --media-only`，不过不开工；人物层 `<OffthreadVideo transparent />`；几何写成相对源宽高的分数。
- 模式 B：说话信号从 `audio.wav` 逐帧算 RMS 生成数据文件，组件只读数据，不手写关键帧。
- 字幕组件素排、整句硬现；位置从常量取（横 bottom 100 / 竖 bottom 350）。
- 交付前跑 `motion_check.py`（模式 A 加 `--baseline` 人物素材和人物区窗口）、`freeze_probe.py`。

**评委关注点**
```
这是知识口播（模式 {A/B}）。请额外：① 写出"他认为 ___，因为 ___"，写不出判 KT1 不通过；
② 模式 A：在人物形态切换前后 ±0.5 秒连抽帧，查字幕或卡片有没有压到脸；模式 B：查有没有任何像口型、表情、手势的动画；
③ 列出所有超过 {5/8} 秒没有画面变化的段落；④ 逐句标出哪些数据句没有证据画面。
```

## 9. 常见坑

1. **把口播做成科普动画**：图形抢满屏，人只剩一个声音，观点没了。口播要让"人和他的判断"一直在场（模式 A 角标常驻；模式 B 形象 + 说话信号常驻）。
2. **全片零素材只有动效 + 人物**：观众看到的是"讲 PPT"（talkcraft ③ 硬规）。数据、新闻、产品句必须有证据画面。
3. **代码画口型**：必僵，一票否决（铁规矩 7）。
4. **字幕压脸**：只在形态切换的窗口里出现，句级抽帧抓不到；切换前后 ±0.5 秒要连抽（talkcraft ⑦ 清单二）。
5. **先做时间戳再剪口水词**：时间轴整体错位，全部重做。顺序是预剪 → 时间戳。
6. **人物素材帧率不对**：25fps 素材塞进 30fps 成片，人每秒卡 5 次（`host-footage.md` §1）。
7. **版式固定**：人物永远左下、素材永远中间方块、文字永远右边，用户会说"过于固定"（talkcraft 2026-09-21 用户反馈）。
