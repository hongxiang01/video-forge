# 类型卡：科普讲解 · 中档（3–5 分钟）

> 中档是 `../pipeline-explainer.md` 默认面向的档位：结构模板（谜题式 / 清单式 / 旅程式）、差异化、写稿、配乐、留存设计都在那里，这里不重复，只补**中档专属的数字、阈值和模板**。
> 写稿原则见 `vendor/anything2explainer/reference/narration-guidance.md`，章法与分镜格式见同目录 `narration-storyboard.md`。
> 数字标注：【源】有出处；【推】推算；【经验】经验值，待发布数据验证。

## 1. 定位与核心问题

**一条主线讲透一个系统或一段过程。** 观众看完能用自己的话复述主题，并且能说出"为什么是这样"（不只是"是什么"）——即 `review-standards.md` 科普类的核心问题。
和短档的区别：短档只给一个答案；中档要让观众理解**一串因果**，所以需要章节、承接和再钩。

## 2. 时长与画幅

| 项 | 建议 | 依据 |
|---|---|---|
| 推荐时长 | 3–5 分钟；首选 3.5–4.5 分钟 | TED-Ed 动画课 3–5 分钟【源 1】；回形针单条约 5 分钟【源 2】；抖音 Vibe 知识视频"三五分钟"【源 3】 |
| 语速假设 | 云希原速 5.5 字/秒；加段内 10 帧、段末 30 帧、章前 45 帧留白后，成片密度 4.0–4.5 字/秒 | `narration-storyboard.md` §1 实测 |
| 字数预算 | 3 分钟 720–810 字；4 分钟 960–1080 字；5 分钟 1200–1350 字 | 【推】按 4.0–4.5 字/秒；写完估时长，超/欠 15% 就加删句子 |

## 3. 结构模板

默认三种结构见 `pipeline-explainer.md`「结构模板」，这里给出**4 分钟片子的时间分配**。

**A. 谜题式（默认推荐）**
| 段 | 做什么 | 时间 |
|---|---|---|
| 处境 + 谜题 | 一个具体处境里冒出一个反常识问题（K1）；说清这题答不出来会怎样（代价） | 0:00–0:20 |
| 第 1 条线索 + 小揭晓 | 给出第一块拼图并兑现一个小答案，证明这片值得看下去 | 0:20–1:00 |
| 第 2、3 条线索 | 每条线索结尾留一个新缺口，下一章从缺口开始（章界起承转合，`narration-storyboard.md` §1）；第 2 条末尾放一次反转 | 1:00–3:00 |
| 汇合 | 线索汇成答案；本片的高光时刻（K6），配主角大画面 | 3:00–3:40 |
| 回扣 | 回到开头处境，用新理解重看它（K7），不罗列总结 | 3:40–4:00 |

**B. 旅程式**——一个物件 / 一个信号从起点走到终点。开头 15 秒交代"它要去哪、路上会出什么事"；中段 3–4 站，每站 45–60 秒，每站一个新障碍（这就是再钩）；最后 30 秒到达终点并回望全程（一张全景图，K13 的"值得回看"）。

**C. 对照式（TED-Ed 常用）**——两种解释 / 两种做法摆在一起，每章用一个新证据让天平倾斜一次。开头 20 秒立两方；中段 2–3 轮证据，每轮 60 秒；最后 40 秒给出判决，并说清楚还有什么不知道（`narration-guidance.md` §6 的"承认不确定"）。

清单式只在内容天然是并列项时用，且要满足 K11。

## 4. 视觉规范

- **主体大小**：每个镜头一个主角，图形主角高 ≥170px 或大字 ≥96px（1920×1080，`narration-storyboard.md` §3）；主角在第 1–2 个节拍内入场。
- **文字上屏**：按 G3（正文 ≥36px，关键词 ≥84px，标注 ≥40px）；同一时刻除字幕外最多 3 个文字元素，其中只有 1 个带强调色（G5）；画面不写口播原句，只写关键词、数字、标签（回形针做法：拟物化 + 关键数据加动效【源 2】）。
- **镜头运动**：每章 ≥3 次有意的运镜（推近、承接位移、整组平移、视差）（`narration-storyboard.md` §3）；运镜不进末拍。
- **转场**：章内镜头之间用运动承接，能不清场就不清场；章首第一个镜头沿用上一章末镜头的元素（K5）。章节卡 ≤2 秒。
- **信息密度**：全片至少一张"暂停才看得全"的图（K13），放在汇合段或旅程终点；其余镜头一屏只讲一个画面关系。
- **固定角色**：概念用固定角色代表，定了就贯穿到底（`pipeline-explainer.md`「写稿」）。
- **进度提示**：横屏可用进度条 + 章名（章名规则见 `narration-storyboard.md` §1：名词短语、≤6 字、不用比喻）；竖屏不用进度条。

## 5. 声音规范

- 配音：云希原速默认；整片一个音色。
- 配乐 BPM：90–110【经验】。100 BPM 时 1 小节 = 2.4 秒，镜头内 2–4 秒的节拍正好落在小节线上。章节切换、关键词、高光落在拍点或小节线上 ±2 帧（K9）。
- 配乐分段：每章可以换配器或加减声部，但 BPM 全片不变（换 BPM 会让 K9 的网格失效）。
- 何时收音乐：① 每章的论点句前收 1–2 小节；② 反转那一刻抽空；③ 回扣段音乐回到开头的动机。全片有意的收放 ≥2 次（`pipeline-explainer.md`「配乐和节奏」）。
- 响度：按 G4。

## 6. 校验逻辑

## 7. 提示词模板

**写稿**
```
写一条 {时长} 分钟的科普解说稿，主题：{一句话主题}；观众：{谁、懂多少}；发布平台：{B站/抖音/YouTube}。
结构：{谜题式 / 旅程式 / 对照式}，按 explainer-mid.md §3 的时间分配。分 {3–4} 章，每章 ≥60 秒，章名是 ≤6 字的名词短语。
预算：{时长×60×4.2 取整} 字（±15%），{句数} 句左右，每句 ≤35 字，用 | 切字幕块（每块 ≤16 字）。
必须：开头放进一个具体处境，第一句就有问题；第 1 分钟内兑现一次小答案；每 {60–90} 秒一个新问题 / 反转 / 揭晓，在句后标【再钩】；
每章末留下下一章要解决的缺口，下一章第一句先接住它；每章一句论点句标【高光】；结尾回到开头处境，不罗列总结。
全片固定用 {固定角色/比喻} 代表 {核心概念}，不中途换比喻。数字只用 {事实清单路径} 里的，并换算成可感的尺度。
每句后写【画面：画面关系（见 narration-storyboard.md §4 左列）+ 主角】。
写完按 narration-guidance.md 的起飞前检查表自查，朗读一遍，交第 2 版。
```

**分镜**
```
根据定稿 {narration.txt} 和 {timeline.md}，按 narration-storyboard.md §3 的格式写分镜表（1920×1080）。
一段 = 一个镜头；目标 {25–35} 个镜头，单镜头 4–15 秒，镜头内每 2–4 秒一个节拍。
每个镜头写：主角·尺寸（图形 ≥170px / 大字 ≥96px）、动效、运镜、持续动作、停留帧数。
全局清单：章界清单（钩子句 / 承接句 / 承接元素）、高光清单（每章 ≤1）、再钩点秒数、运镜清单（每章 ≥3）、
值得回看的那一张图在哪个镜头、BPM {BPM} 下每个章切换落在哪个小节线。
```

**构建 agent 要点**
- 先读：本卡 §4、风格卡、分镜表、kit 与样板镜头；按每句语义从 talkcraft `cards-index` 选动效卡，写进分镜表「动效卡」列（《AI 到底该怎么用》复盘第 1 条）。
- 直接引入 talkcraft 的相机（极缓推拉）和运动承接转场，不自己写叠化。
- 交付本组前自跑 `motion_check.py` / `freeze_probe.py`；帧号全部从 `timeline.ts` 取。

**评委关注点**
```
这是 3–5 分钟横屏科普。请额外：① 用两句话复述主题和"为什么"，复述不出判核心问题不通过；
② 列出小揭晓和每个再钩点的秒数，标出间隔 >90 秒的空档；③ 试着对调任意两章，说清损失了什么；
④ 列出所有超过 15 秒的镜头和"空白纸 + 一句话"的镜头（K8）；⑤ 找出那张值得暂停的图。
```

## 9. 常见坑

1. **镜头太长太少**：16 个镜头撑 4 分钟，每个镜头 14 秒，画面就"不动"了（《AI 到底该怎么用》v1）。按 KM4 拆。
2. **清单式中段像 PPT**：四条要点各配一屏字（同一片的评委意见）。先试谜题式。
3. **章首从零开讲**："接下来我们看 X"是报幕，不是承接（`narration-guidance.md` §13）。
4. **第 1 分钟全是铺垫**：观众在第 1 分钟流失最多（MrBeast 手册，见 `retros/evolution-log.md` 第 2 轮）。
5. **配音后改词**：所有帧号都会变，构建组硬编码的帧号全部作废。定稿前改，定稿后只改章名。
6. **全片一个音量**：配乐没有收放，论点句和铺垫句一样平（`pipeline-explainer.md`「配乐和节奏」）。
7. **整屏文字**：第 1 版《王朝 300 年》"全是文字介绍，太空洞了"。
