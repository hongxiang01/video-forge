# 类型卡：三维微缩 / 交互场景

> 适用：three.js 可拖拽的小场景。两种交付：**① 网页**（主交付，单个 HTML，可发布成 Artifact）；**② 导出视频**（环绕 / 转台展示，可选）。
> 和其它文件的关系：产线步骤见 `../pipeline-diorama.md`，方案与已知坑见 `~/video-forge/recipes/toon-diorama.md`，画风数值见 `~/video-forge/my-styles/toon-rainy-night/STYLE.md`，评委流程见 `../review.md`。本卡只写这个类型**特有**的规格、校验和提示词；编号沿用 `../review-standards.md`（S1–S5、G1–G7），新增从 S11 起。
> 数字来源标注：【源】有出处；【现】取自现有作品 `works/rainy-corner-diorama`（v9）代码 / 画风卡；【经验】经验值，待验证。

## 1. 定位与核心问题

**观众拖着看一圈，每个角度都成立，并且愿意凑近找细节。**（对应 review-standards「拖着看一圈，每个角度都成立吗？」）

它不是视频：没有时间线，观众自己当摄像师。所以"主视角那一眼"决定留不留，"转一圈和凑近看"决定记不记得住。

## 2. 交互规格（网页）/ 时长与画幅（视频）

### 2.1 网页交付

| 项 | 规格 |
|---|---|
| 首屏 | 打开后 ≤ 1 秒出现非白屏的占位（底色 + 底座剪影或加载文字）；桌面宽带 ≤ 3 秒、中端手机 4G ≤ 5 秒出现第一帧完整场景【经验；Web Vitals 的 LCP"良好"线是 2.5 秒【源】，3D 场景放宽】 |
| 第一帧 | 就是默认主视角（S3），不先黑屏再飞入；有自转时首帧已经构图成立 |
| 交互方式 | 拖拽 / 单指旋转，滚轮 / 双指缩放；限制：不能钻到底座下（`maxPolarAngle = 0.46π`【现】）、不能贴脸穿模（`minDistance`【现】）、不能拉到底座变成小点（`maxDistance` 让底座仍占画面宽 ≥ 40%【经验】）；默认不开平移 |
| 自转 | 默认缓慢自转（`autoRotateSpeed 0.25`【现】）；用户一动就停，松手 8 秒后恢复【现】；`prefers-reduced-motion` 时不自转【现】 |
| 引导 | 默认**不加 UI**（toon-diorama 禁区【现】）：靠自转暗示"能转"、光标 `grab / grabbing`。用户要说明文字时写进需求卡，且只在首屏出现、≤ 3 秒淡出 |
| 帧率 | 桌面 ≥ 50 fps（S2）；中端手机 ≥ 30 fps【经验】 |
| 像素比 | `min(devicePixelRatio, 2)`，短边 < 700px 时上限 1.5【现】 |
| 性能预算 | 每帧 draw calls 桌面 ≤ 300、手机 ≤ 150；三角形 ≤ 50 万；实时光源（含阴影投射）≤ 4，其余用烘焙 / 自发光假光【经验】。v9 的"对数深度 + 三遍渲染 + 9 盏灯"已被评委指为偏重【现】 |
| 包体 | 只用 CDN 白名单脚本（cdnjs / jsdelivr / unpkg，Artifact 限制）；不引外部图片和媒体，纹理全部程序化生成；单个 HTML ≤ 16 MB（Artifact 上限），目标 ≤ 300 KB 源码 + three.js【经验；v9 约 124 KB】 |
| 截图模式 | `?shot` 关自转、暴露 `window.__dio = { camera, controls, scene, renderer }`【现】，评委和测量脚本都走这个入口 |
| 兼容 | 桌面 Chrome / Safari、iOS Safari、安卓 Chrome、微信内置浏览器（国内分享最常见的打开方式）都要打开过一次 |

### 2.2 导出视频（环绕 / 转台展示）

| 项 | 规格 |
|---|---|
| 画幅 | 16:9 1920×1080（默认，抖音也发横版、画面不加字——见用户发布习惯）；需要竖版时 1080×1920 单独设机位，不从横版裁 |
| 帧率 | 30 fps 默认【现：v9 视频 1920×1080 30fps】；镜头转得快或雨丝多时 60 fps |
| 时长 | 展示片 20–45 秒（v9 为 45 秒、16 个机位关键帧【现】）；社交平台切条 10–15 秒【经验】 |
| 镜头 | 关键帧数 ≈ 时长 / 3 秒；每个机位停留 2.5–3 秒【现】；关键帧之间缓动（smoothstep），不硬切【现】 |
| 运动速度 | 环绕角速度 ≤ 30°/秒，近景 ≤ 15°/秒，否则描边和细节会抖（judder）【经验】 |
| 结构 | 见第 3 节模板 3 |
| 渲染 | 虚拟时钟逐帧截图（headless Chrome）+ `ffmpeg` 合成，不录屏【现：`works/rainy-corner-diorama/video/render.js`】；雨、闪烁等随机动画用时间做种子，同一帧重渲结果一致 |

## 3. 结构模板

### 模板 1：一个地方 + 一条故事线索（网页默认）

| 层 | 做什么 | 占比（按观众注意力） |
|---|---|---|
| 主视角 | 一眼看懂"这是哪、几点、什么天气"：主体建筑 + 光池 + 一个动的东西（雨、灯、烟） | 首屏 100% |
| 环绕 | 转一圈每 45° 都有新东西：正面招牌、侧面小巷、背面后门，不留"背景板" | — |
| 凑近 | 3–5 个可发现的小物件，至少 1 个讲故事（没关的窗、门口一双鞋、猫在等人）| — |

元素分布：前、中、后三层都有东西；四个象限的细节数量差 ≤ 2 倍【经验】。

### 模板 2：一个对象的展示台（产品 / 收藏品 / 建筑模型）

| 层 | 做什么 |
|---|---|
| 主视角 | 对象 3/4 侧面，占画面 40–60%【经验】 |
| 环绕 | 每个面一个看点（结构、接口、纹理），底座上可以放一两件陪衬说明比例 |
| 凑近 | 材质微距成立（不糊、不破面）；需要时加热点讲解（用户同意加 UI 时） |

可与 `product-ad.md` 联用：网页做展示台，视频导出做产品片的 hero 转台镜头。

### 模板 3：导出视频的环绕片（20–45 秒）

| 段 | 做什么 | 占比 |
|---|---|---|
| 开场全景 | 底座全貌，高机位，像人刚拿起模型 | 0–10% |
| 第一次拖转 | 降低机位看到湿地面 / 主光池 | 10–20% |
| 细节巡游 | 3–5 个细节，每个 2.5–3 秒推近再离开，按空间顺序走，不来回跳 | 20–85% |
| 拉回定格 | 拉回全景，换一个和开场不同的角度收尾，定格 ≤ 3 秒（G7） | 最后 15% |

## 4. 视觉规范

- **模型感**：世界在一块底座上，底座外只有桌面和接触阴影【现】。不画无边的世界。
- **主体**：主视角里主体占画面 30–50%，构图有前景遮挡物（灯杆、招牌、树）增加纵深【经验】。
- **光**：光有来处，亮区是光池，光池之间是暗；环境光压低，不要全局亮（用户原话「灯光拍扁还是过于亮」，第一禁区）【现】。时间段决定光色，画风卡第 3 节只改色彩不改其它数值【现】。
- **材质**：按所选画风卡（三渲二用 `MeshToonMaterial` + 三阶 ramp + 描边【现】）；不混用写实 PBR 和卡通材质。
- **比例**：按真实街道比例，不卡通化【现】；同一场景里门高、台阶、人高一致（人高 ≈ 门高 0.8【经验】）。
- **人物 / 动物 / 车**：小、远、静止或简单循环（SKILL 铁规矩 7）；这一项是 v9 最低分项【现】，不让它们当主角。
- **文字**：招牌只用真实可读的文字，绝不出现镜像字【现】；文字贴图在任何角度都不能从背面透出来。
- **镜头（网页）**：默认视角 32° 左右的窄视场，像长焦看模型，减少透视畸变【现】；低机位才能看到地面倒影【现】。
- **镜头（视频）**：只做"人手拖着转"能做出的运动：环绕、推近、升降；不做穿墙、飞越屋顶内部。

## 5. 声音规范

| 交付 | 规范 |
|---|---|
| 网页 | 默认静音。要声音时：首次点击后才播放（浏览器自动播放限制），右下角不放按钮（禁 UI）时用"点击场景开声"；环境音循环无缝（首尾交叉淡化 ≥ 0.5 秒【经验】）；音量默认 -20 LUFS 左右，比视频低【经验】 |
| 网页空间声（可选） | 用 three.js `PositionalAudio` 把声源挂在物件上（冷柜嗡鸣、贩卖机、雨棚滴水），转到哪边哪边响；距离衰减让凑近才听得清 |
| 视频 | 环境音底 + 2–3 个点状音效 + 可选低音量配乐（雨夜：雨声底 + 车过积水 + 自动门提示音 + 冷柜嗡鸣，配乐 lo-fi 钢琴或电钢【现】）；镜头推近某物件时它的音效同步变大；响度按 G4 |
| 评委限制 | 只测量（响度、峰值、循环接缝处有无爆音），不评价好不好听 |

## 6. 校验逻辑

原编号照写，新增从 S11 起。追问时把本表和"通用"项给用户勾选，以用户确认的评审标准卡为准。G1–G3、G7 只适用于导出视频；网页交付用 S11–S17 代替。

| 编号 | 检查项 | 必须/加分 | 阈值或判据 | 怎么测 |
|---|---|---|---|---|
| S1 | 【工】任意角度没有穿模、破面、空洞 | 必须 | 每 45° 截图 × 3 个仰角（低 8° / 中 20° / 高 35°）共 24 张，无问题 | `?shot` + `window.__dio` 设机位截图，人判 |
| S2 | 【工】【量】交互流畅 | 必须 | 桌面 ≥ 50 fps；程序化拖转 5 秒内最长单帧 ≤ 50 ms | Playwright 里用 `requestAnimationFrame` 记 5 秒帧间隔，同时用 `__dio.controls` 匀速转相机 |
| S3 | 【美】主视角构图成立，有主体、有故事线索 | 必须 | 首帧即主视角；能一句话说出"这是哪、几点、发生了什么" | 默认视角截图，人判 |
| S4 | 【美】细节密度：近看有可发现的小物件 | 加分 | ≥ 3 个可发现物件，至少 1 个讲故事；四个象限细节数差 ≤ 2 倍 | 按元素清单逐项定位截图 |
| S5 | 【美】光影符合场景时间 | 加分 | 每片亮区能指出光源；夜景有反射 | 5 个固定视角截图，人判 |
| S11 | 【工】【量】首屏速度 | 必须 | ≤ 1 秒出占位；桌面宽带 ≤ 3 秒、模拟中端手机 4G ≤ 5 秒出完整首帧 | 页面在首次渲染后写 `window.__dioReady = performance.now()`；Playwright + CDP 限速（下行 9 Mbps、RTT 60 ms，CPU 降速 4 倍）读取 |
| S12 | 【工】【量】手机帧率 | 必须（要在手机上看时） | 模拟中端手机（CPU 降速 4 倍、视口 390×844、DPR 3 被限到 1.5）≥ 30 fps；有条件时真机复测 | 同 S2，开 CDP CPU throttling；真机用远程调试看帧率 |
| S13 | 【工】【量】性能预算 | 加分 | draw calls 桌面 ≤ 300 / 手机 ≤ 150；三角形 ≤ 50 万；投影光源 ≤ 4 | `__dio.renderer.info.render.calls / .triangles`，场景遍历数投影光源 |
| S14 | 【工】交互边界 | 必须 | 拖到极限仰角看不到底座下面；缩到最近不穿模；拉到最远底座仍占画宽 ≥ 40%；自转停 / 恢复符合规格 | 把相机设到 `minDistance / maxDistance / maxPolarAngle` 各截一张；自转用计时脚本测 |
| S15 | 【工】【量】交付合规 | 必须 | 只引 cdnjs / jsdelivr / unpkg 脚本；无外部图片和媒体；HTML ≤ 16 MB；控制台 0 报错 | Playwright 收集 `console` 错误和网络请求域名；`wc -c` |
| S16 | 【工】多端打开 | 加分 | 桌面 Chrome、iOS Safari、安卓 Chrome、微信内置浏览器都能出画面、能拖 | 真机或用户协助各开一次，截图记录 |
| S17 | 【美】默认无 UI 元素、无镜像字 | 必须 | 画面里没有按钮 / 面板（需求卡另有约定除外）；所有文字从正面可读 | 24 张环绕截图里查 |
| S18 | 【工】【量】导出视频的镜头运动 | 必须（导出视频时） | 环绕角速度 ≤ 30°/秒、近景 ≤ 15°/秒；关键帧间缓动无硬切；无抖动 | 从机位关键帧表算角速度；G1 查切换处连抽 3 帧 |
| S19 | 【工】【量】导出视频可复现 | 加分 | 同一帧重渲两次逐像素一致（随机动画用时间做种子） | 抽 3 个时间点各渲两次，比 md5 |
| S20 | 【美】导出视频首帧即全貌 | 加分 | 第 0 帧就是底座全景，不从黑场淡入超过 0.5 秒 | 抽第 0、15 帧，人判 |
| G1、G4、G5、G6、G7 | 通用项 | 见 review-standards | G1 / G4 / G7 只对导出视频测；G5 色板、G6 用户禁区两种交付都查 | 同 review-standards |

## 7. 提示词模板

### 7.1 创意提示词（地点 + 故事线索）

```
为一个放在方形木底座上的 three.js 微缩场景写 {N=3} 个方案。
地点：{地点}；时间与天气：{例：雨夜 23 点}；画风：{画风卡路径}
用户必须出现的元素（编号清单）：{1. … 2. …}
禁区（用户原话）：{…}
每个方案输出：
1. 一句话：观众从主视角第一眼看到什么、能猜到发生了什么故事；
2. 主体建筑 / 对象，占主视角画面多少；
3. 光源清单（每片亮区对应哪盏灯）和光池位置；
4. 环绕一圈每 90° 的看点（4 条），每个象限至少 1 个；
5. 3–5 个凑近才发现的小物件，标出哪个在讲故事；
6. 会动的东西（≤ 3 种，人物只静止或简单循环）。
不写"温馨""有氛围"，写成看得到的物件和光。
```

### 7.2 场景设定（布局）提示词

```
把选定方案 {路径} 写成布局表（JSON）和一张俯视示意（SVG，底座为 {边长} 米正方形，原点在中心）：
每个元素：{ "id": 需求清单编号, "名称", "位置": [x, z], "朝向°", "尺寸": [宽, 高, 深], "层": 前/中/后, "象限": 1–4,
           "光源": 有/无, "是否描边": 是/否, "在哪个固定视角可见": [主视角, 正面, 转角, 小巷, 低机位] }
硬约束：所有元素在底座内；需求清单每一条都有 id 对应；四个象限细节数差 ≤ 2 倍；
人高 ≈ 门高 0.8；投影光源 ≤ 4。输出后用脚本核对这些约束并列出结果。
```

### 7.3 构建 agent 提示词要点

- 从起手文件复制（`works/rainy-corner-diorama/index.html`），保留渲染管线、描边、倒影、雨、底座、机位、`?shot` / `__dio`、自转与 reduced-motion 逻辑，只替换建模部分（`../pipeline-diorama.md`）。
- 先做一个角落定光的风格帧，用户确认亮度 / 对比 / 色调再铺满（复盘教训 1）。
- 性能从第一版就做：合批 / `InstancedMesh`、静态阴影只烘焙一次、灯数按预算；首次渲染后写 `window.__dioReady`。
- 纹理全部程序化（canvas 画招牌、海报），不引外部图片；文字贴图检查镜像。
- 交付前自测并把数值写进说明：S2 / S12 帧率、S11 首屏、S13 draw calls、S15 控制台和网络请求、S1 的 24 张环绕截图。
- 导出视频：机位关键帧表（时间、目标点、方位、仰角、距离）先给用户确认，再用虚拟时钟逐帧渲染（`video/render.js` 做法）。

### 7.4 评委关注点（在 `../review.md` 骨架后追加）

```
本作品类型：三维微缩 / 交互场景（交付：{网页 / 网页 + 视频}）。看作品方式：
- 网页：本地 `python3 -m http.server` 打开 `index.html?shot`，用 `window.__dio` 设机位；
  先截 5 个固定视角（主视角、正面、转角、小巷、低机位），再按 S1 截 24 张环绕图。
- 视频：按 review.md 每 2 秒抽 1 帧。
特别注意：
1. 主视角第一眼：能否一句话说出这是哪、几点、发生了什么（S3）。
2. 环绕截图里有没有"背景板"角度（某个方向什么都没有），有没有镜像字、UI 元素（S17）。
3. 光：每片亮区指出它的光源；整体是否过亮把体积拍扁（画风卡第一禁区）。
4. 量化项（S2、S11–S15）必须给出测量值，不能写"看起来流畅"。
5. 人物、车辆只判是否穿帮和是否抢戏，不按"表演"打分。
```

## 9. 常见坑

已知的技术坑（条纹、发灰、水洼、截图相机乱跳、file:// 打不开、圆角盒 UV）见 `~/video-forge/recipes/toon-diorama.md` 第 7 节，这里只写类型层面的坑。

| 坑 | 后果 | 怎么避 |
|---|---|---|
| 没先出风格帧就建全场景 | 光到第 3 轮才对，前两轮白调（v9 复盘） | 一个角落定光 → 用户确认 → 再铺 |
| 只做好主视角 | 一转过去是背景板 | S1 24 张环绕截图 + 四象限细节数检查 |
| 性能最后补 | 手机打不开或掉到 20 fps | 预算写进构建提示词，第一版就测 S2 / S12 / S13 |
| 只在桌面 Chrome 测 | 微信内置浏览器、iOS Safari 黑屏 | S16 多端各开一次 |
| 加了"拖动旋转"提示面板 | 破坏模型感（UI 是禁区） | 用自转和光标暗示；必须加时 ≤ 3 秒淡出 |
| 人物、车辆当主角 | 最低分项（v9），离"获奖"最远 | 小、远、静止，当线索不当主角 |
| 导出视频时录屏 | 掉帧、卡顿、每次不一样 | 虚拟时钟逐帧渲染，S19 可复现 |
| 视频镜头转太快 | 描边和细节抖 | S18 角速度上限，近景减半 |
| 视频从横版裁成竖版 | 主体被裁、构图失衡 | 竖版单独设机位关键帧 |
| 声音自动播放 | 浏览器拦截、用户被吓到 | 首次交互后才播放，默认静音 |
