# 类型卡：科普讲解 · 短档（≤60 秒）

> 这张卡只写短档和中长档**不一样**的地方。通用流程见 `../pipeline-explainer.md`，通用检查项见 `../review-standards.md`（G*、K*），写稿原则见 `vendor/anything2explainer/reference/narration-guidance.md`。
> 数字标注：【源】有出处，见第 8 节；【推】由其它数字推算；【经验】经验值，待自己的发布数据验证。

## 1. 定位与核心问题

**一个问题，一个机制，一次揭晓。** 观众看完能用一句话说出"原来是因为 ___"，并且想再看一遍或转发。
不适合：需要 3 个以上概念才能讲通的主题。这类主题改做中档（`explainer-mid.md`），或者只截取其中一个"为什么"做短档。

## 2. 时长与画幅

| 项 | 建议 | 依据 |
|---|---|---|
| 推荐时长 | 35–50 秒，上限 60 秒 | 第三方数据：教育类 Shorts 在 35–45 秒、收尾兑现清楚时留存最好【源 4】；YouTube Shorts 以 60 秒为常见上限【源 5】 |
| 语速假设 | edge-tts 云希 `RATE=+0%` 约 5.5 字/秒（`narration-storyboard.md` 实测）；短档把段末停顿压到 15 帧，片头留白 ≤10 帧，成片密度约 4.8 字/秒 | 【推】 |
| 字数预算 | 30 秒：140–155 字；45 秒：210–230 字；60 秒：280–300 字 | 【推】按 4.8 字/秒 |
| 句数 | 45 秒约 12–16 句，每句 ≤20 字（中档上限是 35 字，短档更短） | 【经验】 |
| 镜头数 / 平均时长 | 45 秒 12–18 个镜头，平均 2.5–4 秒；单镜头不超过 6 秒 | 【经验】竖屏推荐流切换快；中档单镜头 ≥4 秒的规矩不适用 |
| 再钩间隔 | 每 10–15 秒一个新拍点（新画面关系、数字落地、反转），全片 3–4 个 | 【经验】；K12 是中长片的规则，短档不适用 |
| 画幅 | **9:16 竖屏 1080×1920**（抖音、视频号、Shorts、Reels）；只有用户明确发 B 站横版合集时才用 16:9 | 平台形态 |
| 帧率 | 30fps（和 Remotion 现有工程一致）；需要更丝滑可 60fps，但帧号阈值要按帧率换算 | |

## 3. 结构模板

**A. 一问一答（默认推荐）**——最适合"为什么 / 会怎样"类问题。
| 段 | 做什么 | 占比（45 秒片） |
|---|---|---|
| 钩子 | 第 0 帧就有主体在处境里，第一句口播就是问题本身或反常识结论（"你喝下去的水，90 分钟后在哪？"） | 0–3 秒 |
| 线索 | 跟着一个主体走进机制：镜头推进 / 剖开 / 放大，2–3 个拍点，每个拍点一个画面变化 | 3–30 秒 |
| 揭晓 | 答案一句话 + 一个让人能感觉到的尺度（换算成日常物） | 30–40 秒 |
| 回环 | 最后一句接回开头画面或开头问题，使首尾能无缝连播 | 40–45 秒 |

**B. 反常识翻转**——"你以为 A，其实是 B"。0–3 秒摆出常识画面；3–15 秒用一个证据把它打破；15–38 秒解释真正的机制；38–45 秒回到开头画面，但已经换了含义。

**C. 一组三连**——"同一件事的 3 个尺度 / 3 种结果"。要求三项递进（小→大、慢→快），不能互换顺序（K11 的短档版）。每项 10–12 秒，最后 5 秒给出把三项连起来的那句话。最容易变成 PPT，只在 A、B 都不合适时用。

## 4. 视觉规范

- **主体大小**：主体占画面高度 ≥35%（约 670px）；全片同一个主体贯穿（Zack D. Films 式："一个人 / 一样东西"从头跟到尾）。
- **安全区（竖屏）**【经验，发布前按平台最新规范核一遍】：主体和关键词放在 y 250–1400；字幕带在 y 1450–1580（与 talkcraft 竖屏字幕 bottom 350px 一致）；y 1600 以下、右侧 150px 不放任何要读的字（G2 的平台遮挡区）。
- **文字上屏**：
  - 字号：竖屏 1080 宽画布上，字幕 ≥48px，关键词 ≥96px，标注 ≥40px（比 G3 等比换算后的下限更严）。
  - 同一时刻画面上最多 1 个关键词 + 1 行字幕；关键词 ≤8 字；字幕块 ≤12 字（竖屏一行放得下）。
  - 不做整屏文字，不做纯标题帧（K1、K8）。
- **镜头运动**：每个镜头都要有一个动作在进行（推、剖、生长、流动），不靠"漂浮"凑动作（`composition-and-light.md` §7）。至少一次"钻进去"式的推近（从外观推到内部 / 从全局推到局部）。
- **转场**：用运动承接（主体位移、推近穿过、形状变形），不用叠化。叠化在高速剪辑里最容易出双影（G1、《AI 到底该怎么用》评委批评过）。
- **信息密度**：每个镜头只讲一个画面关系（`narration-storyboard.md` §4 关系表），一个镜头里只有一个主角带光。
- **首尾帧**：第 0 帧有主体（K1）；最后一帧和第 0 帧的构图能接上，连播时看不出接缝（回环）。

## 5. 声音规范

- 配音：中文默认云希原速（≈5.5 字/秒）；如果用户嫌慢，可以 +8% 到 +15%，并按新语速重算字数。第一句口播从第 0–10 帧开始，不要用中档默认的 40 帧片头留白（`tts_build.py` 的 `LEAD`）。
- 配乐 BPM：110–130【经验】。120 BPM 时 1 拍 = 15 帧，1 小节 = 2 秒，正好对应 2–4 秒的镜头，切镜头落在小节线上（K9）。
- 何时收音乐：揭晓那一句前 0.5–1 拍把音乐抽空（或只留底鼓），揭晓词落地时音乐回来。全片只收 1 次。
- 响度：按 G4（-14 到 -16 LUFS，真峰值 ≤ -1 dBTP，人声段配乐比人声低 ≥10dB）。
- 音效：每个拍点最多 1 个音效；音效不盖住口播的关键词。

## 6. 校验逻辑

| 编号 | 检查项 | 必须/加分 | 阈值或判据 | 怎么测 |
|---|---|---|---|---|
| K1 | 第 0 帧有主体，前 3 秒抛出问题（短档收紧：第一句口播在 0.4 秒内开始） | 必须 | 首句起点 ≤12 帧 | 脚本：读 `timeline.json` 首句 from；抽第 0 帧人判 |
| KS1 | 时长在预算内 | 必须 | ≤60.0 秒；且和需求卡时长偏差 ≤10% | 脚本：`ffprobe -show_entries format=duration` |
| KS2 | 字数和语速不超预算 | 必须 | 字数 ≤ 时长 × 5.0；纯语音语速 ≤6.5 字/秒 | 脚本：统计 `script.json` 字数 ÷ 配音总长 |
| KS3 | 只讲一个核心问题 | 必须 | 能写出一句"原来是因为 ___"；稿子里没有第二个需要单独解释的新术语 | 人判（评委写出那一句） |
| K2 | 每句都有画面动作 | 必须 | 只有文字的句子 = 0 | 逐句对时间轴抽帧人判 |
| K3 | 关键词与口播对齐 | 必须 | ±6 帧 | 脚本：对照词级时间戳 |
| KS4 | 镜头节奏 | 加分 | 平均镜头 2.5–4 秒；没有超过 6 秒的镜头 | 脚本：`ffmpeg -vf "select='gt(scene,0.3)',showinfo"` 取切点，或直接读分镜表帧号 |
| KS5 | 再钩拍点 | 加分 | 每 10–15 秒至少 1 个新拍点，全片 ≥3 个；列出秒数 | 人判 + 分镜表对照 |
| KS6 | 揭晓在后 1/3 | 必须 | 答案那一句落在全片 55%–85% 的位置 | 脚本：时间轴找揭晓句 from ÷ 总帧数 |
| KS7 | 首尾回环 | 加分 | 最后一帧和第 0 帧画面结构相似（同一主体、相近位置）；人判"连播看不出接缝" | 抽首尾帧并排人判；可用 `frame_signature.py` 比较 |
| KS8 | 竖屏安全区 | 必须 | 关键词、主体不进 y>1600、右侧 150px；字幕在 y 1450–1580 | 抽帧叠安全区蒙版，人判 / 像素检测 |
| KS10 | 竖屏字号（G3 的竖屏版） | 必须 | 字幕 ≥48px，关键词 ≥96px，标注 ≥40px（1080 宽画布） | 读样式表常量；抽帧量字高 |
| G4 | 响度 | 加分 | 按 G4 | `ffmpeg -af ebur128=peak=true` |
| G7 | 无 3 秒完全静止 | 必须（短档升级为必须） | 0 段 | talkcraft `freeze_probe.py` / `motion_check.py` |
| KS9 | 尺度可感 | 加分 | 每个数字都换算成日常物，或者被删掉 | 人判（对照 `narration-guidance.md` §4） |

## 7. 提示词模板

**写稿**
```
写一条 {时长} 秒的竖屏科普口播稿，主题：{一句话主题}，观众：{观众与知识水平}。
硬约束：总字数 {时长×4.8 取整} 字左右（±10%）；每句 ≤20 字；只回答一个问题：{核心问题}。
结构用 {一问一答 / 反常识翻转 / 一组三连}（见 explainer-short.md §3）：第一句就是问题或反常识结论，不要"今天我们来聊"；
揭晓放在 55%–85% 处；最后一句接回开头的画面或问题，让首尾能连播。
每个数字换成观众能感觉到的尺度，换不出来就删。只用事实清单里的数字：{事实清单路径}。
每句后面用【画面：…】写这一句画什么（一个主体在做什么动作），画不出来的句子改写。
写完自己朗读一遍，把念着别扭的句子改掉，给出第 2 版。
```

**分镜**
```
根据定稿 {script.json} 和配音时间轴 {timeline.json}，做竖屏 1080×1920 分镜表。
每个镜头一行：| 镜头 | 帧区间 | 对应句 | 主体（占画面高度 ≥35%） | 动作 | 运镜 | 关键词（≤8 字，字号 ≥96px） | 音乐拍点 |
约束：12–18 个镜头，平均 2.5–4 秒，单镜头 ≤6 秒；切点落在 {BPM} BPM 的小节线上（±2 帧）；
全片同一个主体贯穿；转场用运动承接，不用叠化；至少一次推近钻进内部；
标出 3–4 个再钩拍点和揭晓镜头；最后一个镜头的构图要能接回第 1 个镜头。
主体和关键词放在 y 250–1400，字幕带 y 1450–1580，右侧 150px 和 y>1600 不放字。
```

**构建 agent 要点**
- 先读：本卡 §4、风格卡、分镜表、样板镜头源码；短档不用章节卡、进度条、HUD。
- 画布 1080×1920；安全区写成常量，所有文字组件从常量取位置。
- 每个镜头都要有持续动作；交付前自跑 `freeze_probe.py`，0 段静止 >3 秒。
- 帧号从时间轴取，不手填；配音定稿后不再改词。

**评委关注点**（加在 `review.md` 评委骨架后面）
```
这是 ≤60 秒竖屏科普。请额外：① 写出你看完后能说出的那一句"原来是因为 ___"，说不出就判 KS3 不通过；
② 列出所有再钩拍点的秒数和揭晓句的位置百分比；③ 首尾帧并排看能不能连播；④ 在手机尺寸（390px 宽）下看字幕和关键词能不能读。
```

## 9. 常见坑

1. **把中档稿子压缩成短档**：概念一个都没讲透。短档只留一个问题，其余做成系列。
2. **沿用中档默认留白**：`LEAD` 40 帧、`TAIL` 90 帧、段末 30 帧，45 秒的片子会白白浪费 4–5 秒，开头还是空的。
3. **结尾"总结三点"或"关注我"**：破坏回环，也违背 K7。结尾就是揭晓的余波，回到开头那一帧。
4. **关键词放在底部或右侧**：竖屏会被平台的文案区和点赞栏挡住（G2）。
5. **暗色 + 发光 + 粒子 + 电子乐**：短档最容易落进 Vibe 同质化（K10，见 `pipeline-explainer.md`「差异化」）。
6. **镜头太碎没有主体**：切得快不等于每个镜头换一个新东西。主体贯穿，变的是景别和动作。
