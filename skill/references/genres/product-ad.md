# 类型卡：广告 / 产品宣传片

> 适用：6 秒 / 15 秒贴片，30–60 秒产品片，1–2 分钟发布会式 launch film。画面全部代码绘制（canvas / three.js / SVG / Remotion），不用生成式视频模型。
> 和其它文件的关系：追问流程见 `../interview-checklist.md`，卡片格式见 `../card-templates.md`，评委流程见 `../review.md`。本卡只写这个类型**特有**的规格、校验和提示词；检查项编号沿用 `../review-standards.md`（P1–P5、G1–G7），新增项从 P11 起。
> 数字来源标注：【源】有出处（见第 8 节和文末依据）；【经验】经验值，待自己的投放数据验证。

## 1. 定位与核心问题

**观众看完应该：说得出是哪个产品、记住一个卖点、知道下一步做什么。**（对应 review-standards「核心问题：观众记住了哪个产品、哪一个卖点？」）

广告和画风片、科普片的根本区别：每一秒都在为"一个产品 + 一个卖点"服务；美感是手段，不是目的。

## 2. 时长与画幅

### 分档

| 档位 | 推荐时长 | 镜头数 | 平均镜头时长 | 卖点个数 | 产品/卖点首次出现 | 品牌（logo / 名称）露出 | 典型平台 |
|---|---|---|---|---|---|---|---|
| A 贴片 bumper | 6 秒（硬上限，超过就不是 bumper）【源】 | 2–4 | 1.5–2 秒 | 1 个信息【源】 | ≤ 1 秒 | 开头或全程露出 + 结尾 ≥ 1.5 秒 | YouTube bumper、开屏、信息流前贴 |
| B 短广告 | 15 秒 | 4–7 | 2–3 秒 | 1 | ≤ 3 秒（P1） | 前 5 秒内一次 + 结尾 ≥ 2 秒【经验】 | 信息流、抖音 / 视频号广告、贴片 |
| C 产品片 | 30–60 秒 | 8–20 | 2.5–4 秒 | 1–2（P2） | ≤ 3 秒（P1） | 前 5 秒内一次 + 结尾 ≥ 2.5 秒【经验】 | 官网首屏、电商详情、YouTube、B 站 |
| D 发布会片 launch film | 60–120 秒 | 20–40 | 2–4 秒 | 主卖点 1–2（P2）+ 支撑功能 ≤ 4 个快闪（每个 ≤ 3 秒，不算卖点） | ≤ 3 秒出产品局部或剪影；完整亮相可压到 10–15 秒（悬念式） | 结尾定版 ≥ 3 秒【经验】 | 发布会大屏、官网、YouTube 首发 |

说明：
- 时长选择看用途，不看"越长越好"：要"记住名字"选 A/B，要"理解产品"选 C，要"一次性把新品讲完、在大屏放"选 D。用户拿不准时推荐 C 的 30 秒，并同时出一版 6 秒切条（"Tease, Amplify, Echo"：短片预热、长片展开、短片回响【源】）。
- D 档 P2 不放宽：主卖点仍是 1–2 个，其余功能只能快闪；快闪超过 4 个，观众记不住任何一个。
- 镜头数、平均镜头时长都是【经验】区间，用镜头检测脚本量（第 6 节），超出区间先问"是不是故意的"，不直接判错。

### 画幅与技术规格

| 项 | 规格 |
|---|---|
| 画幅 | 16:9 1920×1080（YouTube、官网、发布会）；9:16 1080×1920（抖音、视频号信息流）；1:1 1080×1080（可选，电商）。一次交付多画幅时，**分镜阶段就按最窄画幅定安全区**，不靠事后裁切 |
| 帧率 | 30 fps 默认；产品旋转、液体、光扫多的片子用 60 fps |
| 安全区 | 文字、logo 不进平台遮挡区（G2）；9:16 上下各留 ≈ 15% 给平台 UI【经验，以平台最新规范为准】 |
| 编码 | H.264 High，yuv420p，码率 1080p30 ≥ 12 Mbps、1080p60 ≥ 20 Mbps【经验】；渐变和暗部查色带（F4） |

## 3. 结构模板

每个模板写"段落 → 做什么 → 占比"。按档位挑，追问"结构"时给用户 2–3 个选。

### 模板 1：问题 → 产品 → 证明 → 行动（适合 B、C 档；最稳）

| 段 | 做什么 | 占比 |
|---|---|---|
| 钩子 | 0 帧就有画面主体；一个观众熟悉的痛点画面或反常识的瞬间 | 0–10% |
| 产品入场 | 产品带着卖点进来：卖点用**画面动作**演示（不是贴参数） | 10–35% |
| 证明 | 同一卖点换 1–2 个角度验证：对比、数字放大、使用场景 | 35–75% |
| 定版 | 产品全貌 + logo + 一句话 + 行动号召（价格 / 上市时间 / 去哪买） | 最后 15–25% |

### 模板 2：揭晓式 reveal（适合 C、D 档；发布会感）

| 段 | 做什么 | 占比 |
|---|---|---|
| 悬念 | 只给局部：轮廓光扫过边缘、材质微距、剪影；配乐压低 | 0–15% |
| 揭晓 | 短暂停顿后最大的一下（停顿 → 最响的一击）：产品完整亮相 + 名字 | 15–25% |
| 卖点段 | 主卖点 1–2 个，每个一组镜头（局部 → 演示 → 数字）；支撑功能快闪 | 25–80% |
| 爆点 | 全片唯一一次能量峰：最快的剪辑、最满的画面 | 75–85% |
| 定版 | 产品回到 hero 角度 + logo + 上市信息 | 最后 10–15% |

（"3 秒内钩子、中段一个爆点、最响的一击前先停一下"借自 huashu-motion 的节奏表做法【源】。）

### 模板 3：一句话贴片（A 档专用）

| 秒 | 做什么 |
|---|---|
| 0–1 | 产品 + 品牌同时出现（或品牌色铺满 + 产品轮廓） |
| 1–4.5 | 一个信息，一个动作：比如"薄"就让产品从一张纸的侧面滑过 |
| 4.5–6 | 定版：logo + 一句话，静止 ≥ 1.5 秒 |

不要把 15 秒素材加速塞进 6 秒（声音会变得慌张）【源】；多个卖点就做多条 bumper，每条讲一个【源】。

## 4. 视觉规范

### 品牌元素
- 用户必须提供：logo 矢量文件（SVG / AI 导出）、品牌色（HEX）、品牌字体或允许替换的字体、产品实物图或 3D 文件。没有就不开工（P3、P5 依赖这些）。
- 色板**从产品本身取**：外壳色、UI 主色、品牌色；风格卡里写死，全片只用这些（G5）。
- logo 不变形、不改色、不加特效描边；最小尺寸按品牌规范，没有规范时 1920 宽画布上 logo 高度 ≥ 80px【经验】。

### 产品呈现
- **产品是主角**：hero 镜头里产品占画面面积 ≥ 25%（16:9）【经验】；每个卖点镜头至少有一帧能看清产品。
- **外观准确**：比例、颜色、按键 / 接口位置对照实物图（P5，用户给实物图时一票否决）。代码建模时先出一张"建模 vs 实物"并排图请用户确认，再做动画。
- 卖点演示用动作：防水 → 水流过表面；快 → 进度条对比；轻 → 和日常物体并排放上天平。不许整屏参数表（P2、P12）。
- **不画写实人物**（SKILL 铁规矩 7）：需要"人在用"时，只出手的剪影、局部（手指点按）、或 UI 屏幕内的内容。

### 光与材质（代码绘制的做法）
- 三点光：主光 45° 侧上，轮廓光从背后勾出边缘（深色产品必须有），补光压低。
- 背景纯色或大渐变，背景亮度和产品错开（深产品配中灰 / 品牌色，浅产品配深底），产品边缘对比度要清楚。
- 金属 / 玻璃用环境贴图（three.js `PMREMGenerator` + 程序化渐变环境）和一条"光扫"高光带横过表面——这是高级感最便宜的来源。
- 暗部和大渐变加抖动，防色带（F4）。

### 镜头运动
- 产品转台：匀加速进、匀减速出，不匀速；单个镜头旋转 ≤ 90°【经验】。
- 微距推进：从材质 / 接口特写拉到全貌，或反过来。
- 转场优先**借产品几何做匹配剪辑**：镜头穿过摄像头模组、沿边框滑入下一个场景（Apple 发布会视频的做法【源】）。少用通用擦除 / 缩放转场；静态"翻页"式转场会显得过时【源 huashu-motion】。
- 每个镜头一个主意，一个焦点（D3 的思路用在广告上）。

### 文字
- 字号守 G3；每屏 ≤ 1 句话 + 1 个数字（发布会大屏同理，"一页一句"【源 小米】）。
- 一屏里样式改动 ≤ 3 处：改了颜色就不再改字重，用了特殊样式就不改颜色【源 小米】。
- 数字要有来源（借 K4）；涉及"最""第一"等极限词，先确认有依据并符合当地广告法（国内广告法禁用无依据的绝对化用语）。
- 中文字体用可商用的开源字体（思源黑体 / 思源宋体等），品牌字体以用户授权为准。

## 5. 声音规范

| 项 | 规范 |
|---|---|
| 配乐 | 按节奏表先定 BPM；剪辑点、卖点出现、揭晓落在拍点或小节线（借 K9 的做法，量法同 M1：±2 帧）。A 档用一个完整的短乐句，不要截断长曲 |
| 停顿 | 揭晓 / 爆点前留 0.3–0.8 秒的收（配乐降或静）【经验】，最响的一击跟在停顿之后 |
| 音效 | 每个"落地"动作配一个音效（产品落定、文字出现、开关）；音效和动作对齐 ±2 帧【经验】 |
| 旁白 | 有旁白时，品牌名至少念一次（Google ABCD 建议品牌在声音里出现）【源】；行动号召用旁白再说一遍【源】。旁白期间配乐低于人声 ≥ 10 dB（G4） |
| 静音可看懂 | 信息流（抖音 / 视频号）常静音自动播放：卖点和行动号召必须在画面上出现，不能只在旁白里 |
| 响度 | 网络平台按 G4：约 -14 到 -16 LUFS，真峰值 ≤ -1 dBTP。电视 / 院线另按交付规范（中国广电、EBU R128 为 -23 LUFS、美国 ATSC A/85 为 -24 LKFS）【源：各标准】 |
| 评委限制 | 评委只测量，不评价好不好听（`../review.md` 原则 5）；配乐、旁白音色由用户判 |

## 6. 校验逻辑

【美】【工】【量】含义同 `review-standards.md`。原编号照写，新增从 P11 起。追问时把本表连同"通用"项给用户勾选，最终以用户确认的评审标准卡为准。

| 编号 | 检查项 | 必须/加分 | 阈值或判据 | 怎么测 |
|---|---|---|---|---|
| P1 | 【美】前 3 秒出现产品或核心卖点 | 必须 | A 档 ≤ 1 秒；B/C/D 档 ≤ 3 秒（D 档悬念式可只出局部，完整亮相 ≤ 15 秒） | 抽 0–3 秒每 10 帧一帧，人判 |
| P2 | 【美】只讲 1–2 个卖点，每个都有画面演示 | 必须 | 卖点数 ≤ 2；D 档快闪功能 ≤ 4 个、每个 ≤ 3 秒 | 按分镜表逐段列卖点，人判 |
| P3 | 【美】品牌元素露出时长、位置符合要求 | 必须 | 默认：前 5 秒内露出 1 次 + 结尾定版（A ≥1.5s / B ≥2s / C ≥2.5s / D ≥3s）；用户给品牌规范时以规范为准 | 抽帧找 logo 帧，记秒数；可用 OpenCV 模板匹配辅助 |
| P4 | 【美】结尾有明确的行动号召或记忆点 | 加分（C/D 档建议转必须） | 定版帧上有：logo + 一句话 + 行动（价格 / 日期 / 去哪） | 末 3 秒抽帧，人判 |
| P5 | 【工】产品外观准确 | 一票否决（用户提供实物图时） | 比例误差 ≤ 3%、颜色 ΔE ≤ 5、部件位置一致【经验】 | 实物图和 hero 帧并排叠图；色值用取色脚本比 |
| P11 | 【工】【量】镜头节奏落在档位区间 | 加分 | 平均镜头时长在第 2 节档位区间内；没有短于 0.4 秒的意外碎镜头【经验】 | `ffmpeg -i f.mp4 -vf "select='gt(scene,0.3)',showinfo" -f null -` 取切点，算镜头数和平均时长 |
| P12 | 【美】（P2 的细化测法）每个卖点由画面动作演示，不是参数文字 | 必须 | 逐个卖点写出"演示动作"；只有文字的卖点 = 不通过 | 按分镜表 + 抽帧对照（同 K2 的做法） |
| P13 | 【美】静音可看懂 | 加分（9:16 信息流必须） | 关掉声音，能说出产品名、卖点、行动号召 | 静音看全片，人判 |
| P14 | 【工】【量】画面 / 剪辑点卡音乐 | 加分 | 揭晓、卖点出现、主要切点落在拍点或小节线 ±2 帧 | 节拍表（librosa / aubio）对照 P11 的切点 |
| P15 | 【美】产品主体在 hero 镜头里够大、够清楚 | 必须 | hero 帧产品面积 ≥ 25%（16:9），边缘和背景对比清楚 | 抽 hero 帧，掩膜算面积占比 |
| P16 | 【工】文字合规 | 必须 | 无无依据的极限词（"最""第一""100%"）；数字有出处（借 K4） | 列出全片文字，逐条对照依据清单 |
| P17 | 【工】【量】多画幅交付时每个画幅都过安全区 | 必须（多画幅时） | 文字、logo、产品主体都在该画幅安全区内 | 每个画幅每 2 秒抽 1 帧，叠安全区遮罩查 |
| P18 | 【工】A 档时长合规 | 必须（A 档） | 时长 ≤ 6.00 秒 | `ffprobe -show_entries format=duration` |
| G1–G7 | 通用项 | 见 review-standards | G3 字号、G4 响度、G7 无 3 秒以上静止（定版除外）在本类型都默认带上 | 同 review-standards |

可借用的其它类型项：F3（光照方向一致，产品片尤其要查反射）、F4（色带）、K4（数字出处）、K9（卡拍）。

## 7. 提示词模板

### 7.1 创意 / 脚本提示词

```
你是广告创意。为下面的产品写 {N=3} 个方向的 {档位: 6 秒 / 15 秒 / 30–60 秒 / 60–120 秒} 广告脚本。
产品：{产品名}，{一句话是什么}；目标观众：{谁}；平台与画幅：{平台} {16:9/9:16}
唯一主卖点：{卖点 1}（可选第二卖点：{卖点 2}）；证据：{数字 / 对比 / 场景，附出处}
品牌：logo {路径}，品牌色 {HEX}，语气 {例：克制 / 俏皮 / 专业}
行动号召：{价格 / 上市时间 / 去哪买}
禁区（用户原话）：{…}
约束：
- 画面全部代码绘制；不出现写实人物表演，只能用手部剪影、局部、UI 内容。
- 第 {1 或 3} 秒内出现产品或卖点；每个卖点写出"画面演示动作"，不许用参数文字代替。
- 结构从这三种里选一种并写明：问题→产品→证明→行动 / 揭晓式 / 一句话贴片。
- 每个方向输出：一句话创意、结构名、逐秒表（秒 | 画面 | 动作 | 文字 | 声音）、品牌露出秒数、卖点出现秒数、为什么观众会记住它。
- 不写"高级""震撼"这类词，写成画面。
```

### 7.2 分镜提示词

```
把已确认的脚本 {路径} 拆成分镜联系表数据（JSON），每格：
{ "shot": 序号, "t_in": 秒, "t_out": 秒, "画面": 具体到产品角度和背景色, "镜头": 推/拉/转台角度°/匹配剪辑, "卖点": 无或卖点编号,
  "演示动作": 具体动作, "文字": 原文（≤1 句 + 1 个数字）, "声音": 拍点/音效/旁白原文, "品牌露出": true/false }
硬约束：总时长 = {秒}；镜头数 {区间}；平均镜头时长 {区间}；第一个卖点 t_in ≤ {秒}；
定版 ≥ {秒} 且含 logo + 行动号召；所有颜色只用风格卡 {路径} 的色板；文字在 {画幅} 安全区内。
输出后用脚本核对：总时长、镜头数、平均时长、卖点出现秒数、品牌露出秒数，不符合就改到符合再交。
```

### 7.3 构建 agent 提示词要点

- 输入只给：确认后的分镜 JSON、风格卡、产品资产（logo SVG、实物图、色值），不给其它方向的废稿。
- 先做"建模 vs 实物"并排图（P5）和 1 张 hero 风格帧，过了再做动画。
- 时间轴由分镜 JSON 驱动（Remotion 用 `at()` 锚点，canvas / three.js 用虚拟时钟逐帧渲染），不手写魔法数字。
- 光扫、匹配剪辑、转台缓动做成可复用函数；转台用缓入缓出，单镜头 ≤ 90°。
- 自查后再交：跑 P11 镜头检测、P18 时长、G4 响度（`ffmpeg -af ebur128`）、`freezedetect` 查 3 秒以上静止（G7），把测量值写进交付说明。
- 多画幅：每个画幅单独渲染、单独过 P17，不从 16:9 直接裁。

### 7.4 评委关注点（在 `../review.md` 骨架后追加）

```
本片类型：广告 / 产品宣传（{档位}）。除评审标准卡外，判定时特别注意：
1. 关掉声音看一遍：能否说出产品名、主卖点、行动号召（P13）。
2. 列出全片每个卖点及其"演示动作"，只有文字的卖点直接判不通过（P2、P12）。
3. 记下 logo / 品牌名每次出现的秒数和时长，对照 P3 阈值。
4. hero 帧与实物图并排比较外观（P5），给出不一致的部件和色值。
5. 用切点检测给出镜头数、平均镜头时长（P11），并核对揭晓 / 卖点是否在拍点上（P14）。
不判断配乐和旁白好不好听，只测响度和对位。
```

## 9. 常见坑

| 坑 | 后果 | 怎么避 |
|---|---|---|
| 卖点堆太多（把参数表都放进去） | 观众一个都没记住 | P2：主卖点 ≤ 2；其余做成快闪或单独切条 |
| 卖点只贴文字 | 像 PPT，静音时等于没讲 | P12：每个卖点写演示动作，分镜阶段就拦下 |
| 代码建的产品和实物比例 / 颜色不对 | 品牌方一票否决 | 动画前先过"建模 vs 实物"并排图（P5） |
| logo 只在结尾出现 1 秒 | 前面流失的观众没看到品牌 | P3：前 5 秒一次 + 结尾定版够长 |
| 把 15 秒剪辑加速成 6 秒 | 节奏慌、音乐变调 | A 档单独设计（模板 3） |
| 产品转台匀速、背景和产品同亮度 | 显得廉价、像模型预览 | 缓入缓出 + 轮廓光 + 背景亮度错开 + 光扫 |
| 从 16:9 直接裁成 9:16 | 字和 logo 被平台 UI 盖住 | 分镜按最窄画幅定安全区，P17 每画幅单测 |
| 写实人物出镜 | 代码画的人必僵（SKILL 铁规矩 7） | 只用手部剪影、局部、UI 内容 |
| 无依据的"最""第一" | 国内广告法风险 | P16：每个极限词要有出处，或改成限定说法 |
| 配乐全程同一音量 | 揭晓没有冲击力 | 揭晓前先收 0.3–0.8 秒，再给最响的一击 |
