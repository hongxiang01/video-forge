# 类型卡：特效 / 视觉奇观片（炫技、粒子、转场秀）

画面全部代码绘制（canvas 逐帧 / Remotion / three.js），不用生成式视频模型。本卡只写这一类片子特有的时长、结构、规范、校验和提示词。通用检查项见 `../review-standards.md` 的 G*、F*，这里引用原编号，新增从 F10 起。配乐卡点和 MV 共用一套拍点做法，见 `music-video.md` 第 4、5 节。

数字标注：「来源：…」= 有出处；「经验值」= 没有可靠出处，先这么用，做完几支片按复盘调。

## 1. 定位与核心问题

**观众看完应该：记住一个想截图、想倒回去重看的瞬间（高光帧），并且相信它——它有重量、有因果、有铺垫，不是一堆效果的随机堆叠。**

奇观的力量来自"预期 → 兑现"：先让观众知道"要来了"，再给一个超出预期的画面。没有铺垫的爆点只是噪音（F6）。

## 2. 时长与画幅

推荐 128 BPM：1 小节 = 1.875 秒，8 小节 = 15.0 秒、16 小节 = 30.0 秒、32 小节 = 60.0 秒，段落和时长都是整数，方便卡点（算术，可直接用 `code_score.py --bpm 128 --bars 16`）。

| | 短爆点片 | 转场秀 / 形变链 | 长版（演示片式，可选） |
|---|---|---|---|
| 时长 | 15–30 秒（8–16 小节） | 30–60 秒（16–32 小节） | 2–5 分钟（经验值，参考演示片 demoscene） |
| 镜头/段数（经验值） | 1–3 个镜头，常一镜到底 | 8–16 次转场 | 6–12 个场景 |
| 平均镜头时长（经验值） | 一镜 10–30 秒，镜内每 2 小节变一层 | 1–2 小节（128 BPM 约 2–4 秒） | 10–30 秒 |
| 高光帧位置 | 全长 50–75% 处（经验值；30 秒片在第 15–22 秒） | 每 4 次转场一个小高光，最后一次最大 | 每场一个，全片在后 1/3 |
| 和音乐结构的对应 | intro=建立 → build=积累 → （抽空）→ main 第 1 拍=释放 → outro=余波 | 每次转场落一个小节线；音乐每 4 小节升一层，画面升一级 | 一段乐曲一个场景，段落切换=场景切换 |
| 画幅 | 默认 16:9 横版 1920×1080（用户抖音作品的固定做法）；用户要竖屏再出 1080×1920，高光主体放在画面中部 60% 安全区（经验值） | 同左 | 16:9 |
| 帧率 | 60fps（快速粒子和转场在 30fps 下易频闪；若受渲染时长限制用 30fps，必须加运动模糊，F15） | 60fps | 60fps |

## 3. 结构模板

### A. 蓄力—释放（单爆点，推荐，16 小节 / 30 秒 @128 BPM）

| 段 | 小节 | 做什么 |
|---|---|---|
| 建立 | 1–2 | 第 0 帧就有一个好看的主体（不是黑屏和标题），只有一种元素，规则一眼看懂 |
| 积累 | 3–8 | 每 2 小节加一层：数量 ×2、速度、尺度、颜色之一；观众开始预感 |
| 蓄力 | 9–10 | 收：向一点压缩、变暗、变慢；第 10 小节最后半小节几乎静止（"吸气"） |
| 释放 | 11 第 1 拍 | **高光帧**：尺度跳变 / 结构翻转 / 一变万；音乐 main 段第 1 拍 |
| 余波 | 11–14 | 在释放后的新世界里漫游，二级运动（碎片落定、波纹扩散）给"可信"（F2） |
| 收 | 15–16 | 慢下来；末帧接回首帧可无缝循环（F14），或定格在高光的余韵 |

### B. 转场秀 / 形变链（30–60 秒）

- 一条"形状接力"：上一镜结束的形状 = 下一镜开始的形状（圆 → 瞳孔 → 行星 → 水滴），每次转场正中间落在小节线。
- 每 4 次转场升一级（材质更复杂、尺度更大、速度更快），最后一次接回第一镜，形成闭环。
- 转场手法轮换：遮罩擦除、填满再拉出（matchCut）、钻进镜头（lensReveal）、对数推拉穿越尺度——写法见 `vendor/huashu-art-motion/references/09-视频动画语法.md` y1 节。同一手法不连续用 3 次以上（经验值）。

### C. 尺度穿越 / 无限缩放（一镜到底，15–30 秒）

- 相机按对数速度推近（每 2 小节进入一个新尺度层），"世界画布按相机矢量重画"，放大多少倍都不糊（huashu 09 跨语法规律第 1 条）。
- 最深一层的样子 = 最外一层，末帧与首帧重合，抖音自动重播时无缝。
- 能量曲线靠推进速度和层的复杂度，不靠闪白。

## 4. 视觉规范

**卡点规则**

| 事件 | 落在哪 | 容差 |
|---|---|---|
| 释放 / 高光帧 | main 段第 1 拍（beats.json `sections.main.frame`） | ±1 帧（F11；比 M1 的 ±2 帧严，因为全片只有这一下，经验值） |
| 转场正中间 | 小节线（`downbeat: true`） | ±2 帧（同 M1） |
| 层叠加、元素出现 | 拍点 | ±2 帧 |
| 冲击动作与音效起音 | 同一帧 | ±3 帧（huashu `05-节奏与配乐.md`：动作帧对齐音频 onset 误差 3 帧以内） |
| 镜头冲击（缩放 1.03→1.0，约 20 帧） | 与转场起点同一拍 | 听感的"咔"和视觉的顿挫是同一下（huashu 05） |

**能量曲线**：写成和 MV 一样的 `arc`（0..1）：建立 0.2 → 积累线性爬到 0.6 → 蓄力末尾压到 ≤0.15 → 释放 1.0 → 余波 0.5 → 收 0.2。成片画面变化量曲线应和它同形（F11）。

**高光帧**（F1）：单帧截出来成立——有明确主体、有尺度参照（一个小东西衬出大）、光的方向一致（F3）。亮度别爆：高光帧里纯白像素（RGB 都 ≥250）占比 ≤15%（经验值），否则截图是一片白。

**运动可信**（F2）：主体有预备、过冲、回弹（缓动用 `expoOut`、`spring`、`smooth` 一类，不用线性）；粒子用"少数大、多数小"的尺寸分布，有寿命和拖尾；碎片有重力和落定。

**因果**：特效要有"谁引起的"。北京冬奥开幕式的雪花随演员脚步被推散（第 8 节）——效果响应一个主体的动作，比满屏自己飘可信得多。

**母题与差异化**：全片一种核心元素贯穿并变形（学 debris：同一种"碎块"从小尺度破坏到撕开天空）。不落入"暗底 + 发光线条 + 蓝紫粒子"的默认样子，除非用户点名（同 K10 的思路，F19）。

**颜色**：只用风格卡颜色，强调色每镜 1 个（G5）。暗部和渐变区加 1–2/255 的抖动噪点防色带（F4，经验值）。

**文字**：奇观片默认画面不加字（用户抖音做法）；要标题的放在第 0–1 秒或最后 1 小节，不压高光。

## 5. 声音规范

| 项 | 规范 |
|---|---|
| 音乐来源与授权 | 默认用 `~/video-forge/tools/music/code_score.py` 代码作曲（可放心发布）；用户给现成曲子时在需求卡写授权情况，拍点表走 mv-director `listen.py` 的 `song.json` |
| 拍点表 | `code_score.py --bpm 128 --bars 16 --fps 60 --out <名>` → `<名>.beats.json`。分镜和构建只引用 `sections.main.frame`、`beats[i].frame`，不手写秒数。默认 `--fps 30`，渲 60fps 时必须传 `--fps 60` |
| 段落 | code_score 固定 intro → build → main → outro；释放对 `main` 起点。两个限制：① 段落比例写死（intro 前 2 小节、build 到 n/3、main 到倒数第 2 小节），16 小节时 main 从第 6 小节（0 起算 bar 5，9.375 秒，约全长 31%）开始，**比模板 A 的第 11 小节早**——用 code_score 时要么把释放放在 main 起点、把余波拉长，要么等工具加段落参数；② main 前**没有抽空的那一拍**，"吸气"只能靠画面做，或者手动把 build 最后半小节的 MIDI 音符删掉再渲 |
| BPM | 爆点片 120–140（128 推荐，见第 2 节算术）；慢变形/尺度穿越 80–100（经验值） |
| 静默段 | 释放前 0.5–1 拍抽空（声音和画面一起收，经验值）；全片不能有 >3 秒完全静止（G7） |
| 音效 | 释放前的上扬（噪声扫频 / 反向混响，持续 1–2 小节），释放那一帧的冲击（低频 + 瞬态），余波的尾音。这和 huashu 05"速通片段间不加嗖声"不冲突：那条是讲段间硬切的蒙太奇，奇观片的蓄力需要上扬 |
| 响度 | -14 到 -16 LUFS，真峰值 ≤ -1 dBTP（G4）；冲击声不要靠压爆峰值，留够余量 |

## 6. 校验逻辑

| 编号 | 检查项 | 必须/加分 | 阈值或判据 | 怎么测 |
|---|---|---|---|---|
| G1/G2/G3/G5/G6/G7 | 通用项 | 按 review-standards | 见原文 | 见原文 |
| G4 | 响度 | 加分 | -14 到 -16 LUFS，TP ≤ -1 dBTP | `ffmpeg -i out.mp4 -af ebur128=peak=true -f null -` |
| F1 | 高光帧单独成立 | 必须 | 评委从全片抽帧里挑出 1 帧，说出主体和尺度参照；纯白像素占比 ≤15%（经验值） | 抽帧人判 + 像素统计脚本 |
| F2 | 运动有重量、惯性 | 必须 | 主体运动没有匀速段直接起停；粒子无断层 | 关键动作前后各连抽 6 帧人判 |
| F3 | 光照一致 | 必须 | 同镜头内阴影/高光方向一致 | 抽帧人判 |
| F4 | 无色带、压缩伪影 | 必须 | 暗部和渐变区放大 400% 无明显台阶；编码 `-crf ≤18 -pix_fmt yuv420p`（经验值） | 抽帧放大人判 |
| F5 | 特效服务于表达 | 加分 | 分镜里每个特效写了它表达什么 | 对照分镜人判 |
| F6 | 有铺垫和蓄力 | 加分（爆点片改必须） | 释放前 ≥4 小节在积累，释放前 1 小节画面变化降到峰值的 30% 以下（经验值） | 帧差曲线（同 mv-director check.py 的算法：160×90 灰度帧差） |
| F10 | 第 0 帧有主体 | 必须 | 首帧非纯色/非纯标题，主体面积 ≥ 画面 5%（经验值） | 抽首帧 |
| F11 | 释放落在拍上、能量同形 | 必须 | 帧差峰值帧离 `sections.main.frame` ≤1 帧；帧差曲线与 arc 相关 ≥0.4（沿用 mv-director 门槛） | 帧差脚本 + beats.json |
| F12 | 闪烁安全 | 必须 | 任意 1 秒内大面积闪烁（亮度大幅反复变化）≤3 次。来源：[WCAG 2.3.1 三次闪烁阈值](https://www.w3.org/WAI/WCAG21/Understanding/three-flashes-or-below-threshold.html) | 逐帧平均亮度序列，数 1 秒窗口内正负跳变对（跳变量阈值按 WCAG 的 10% 相对亮度变化） |
| F13 | 画面只由 t 决定 | 必须 | 同一帧单独渲 2 次、顺序渲到该帧 1 次，三张图 md5 相同 | 脚本（粒子模拟必须是固定种子 + 按帧缓存或闭式公式，不许依赖上一帧状态；mv-director 铁规矩 4） |
| F14 | 可无缝循环（选了循环时） | 加分 | 末帧与首帧 SSIM ≥0.95（经验值）；音乐末尾接回开头不断拍 | `ffmpeg` ssim 滤镜 + 听首尾拼接 |
| F15 | 快速运动不频闪 | 加分 | 单帧位移 > 画宽 1/40 的物体有运动模糊（子帧累积 ≥4 次，经验值） | 抽快速段连续帧人判 |
| F16 | 音画冲击同帧 | 加分 | 每个冲击音效起音与画面冲击帧差 ≤3 帧（huashu 05） | onset 检测（librosa）对帧差峰值 |
| F17 | 有因果 | 加分 | 每个大效果能指出"谁引起的"（主体动作、上一镜的形状、音乐事件） | 对照分镜人判 |
| F18 | 转场秀：形状接力 | 必须（转场秀档） | 每次转场前后两帧能指出共享的形状/颜色/位置；转场中点在小节线 ±2 帧 | 转场处连抽 3 帧 + beats.json |
| F19 | 不落入默认样子 | 加分 | 和同类热门放一起能一眼区分：不是"暗底+发光线+蓝紫粒子"（用户点名除外） | 人判 |

一票否决默认带 G6；F12 不过不许发布（光敏性癫痫风险）。

1. 高光帧一句话（截出来是什么画面，主体 + 尺度参照 + 光）

## 9. 常见坑

1. **效果堆叠无铺垫**：一上来就满屏粒子，后面没处升级。从一种元素、少量开始。
2. **粒子模拟依赖上一帧**：单帧重渲结果不同，分段并行渲染后接缝跳变。固定种子 + 按帧缓存（F13）。
3. **爆点处只有闪白**：亮了一下但画面本身没变，截图是一片白（F1 纯白占比）。释放要是结构/尺度的变化。
4. **为了刺激连续闪**：超过 3 次/秒有光敏风险（F12），也廉价。
5. **暗部渐变色带**：发光、雾、暗底最容易出台阶，8bit 编码前加抖动噪点、降低 crf（F4）。
6. **30fps 快速运动频闪**：用 60fps，或加子帧运动模糊（F15）。
7. **默认赛博配色**：暗底 + 蓝紫发光 = 一眼同质（F19）。
8. **beats.json 帧号对不上**：code_score 默认 30fps；渲 60fps 要传 `--fps 60`。
9. **释放前音乐没抽空、释放位置被工具定死**：code_score 的 build 直接接 main，没有"吸气"；main 固定从约 1/3 处开始。分镜前先读 beats.json 的 `sections`，按实际 main 起点排结构，不要按模板 A 的小节号硬套。
10. **竖屏高光在边缘**：平台按钮栏和文案区盖住（G2），主体放中部。
