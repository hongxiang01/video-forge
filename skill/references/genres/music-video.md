# 类型卡：音乐 MV（整曲 / 副歌卡点短片 / 歌词视频）

生产交给 mv-director（`~/.claude/skills/mv-director`），关卡见 `../pipeline-mv.md`。本卡只写**这一类片子和别的类型不一样的地方**：时长、结构、卡点规范、校验阈值、提示词。通用检查项见 `../review-standards.md` 的 G*、M*，这里引用原编号，新增从 M10 起。

数字标注：「来源：…」= 有出处；「mv-director」= 来自它的 `check.py` / `审片.md` 现有门槛；「经验值」= 没有可靠出处，先这么用，做完几支片再按复盘调。

## 1. 定位与核心问题

**观众看完应该：关掉声音还能说出这首歌讲了什么；开着声音觉得画面"长在音乐上"，并且记住一个会随歌升级的画面（母题）。**

三档的侧重不同：

| 档位 | 观众看完应该 |
|---|---|
| 整曲 MV | 跟着一个主角/母题走完一个有起伏的故事，最后一次副歌是全片最大的一下 |
| 副歌卡点短片 | 前 1 秒就被音乐和画面同时抓住，看完想再听一遍（会重播） |
| 歌词视频 | 每一句都读得清、读得舒服，字本身在"演"这句话 |

## 2. 时长与画幅

| | 整曲 MV | 副歌卡点短片 | 歌词视频 |
|---|---|---|---|
| 时长 | 等于歌曲长度（流行歌常见 3–4.5 分钟）；可删前奏/间奏，删后仍从小节头进、在乐句尾出 | 30–60 秒：铺垫 4–8 小节 + 副歌 8–16 小节（120 BPM 时 1 小节 = 2 秒，16 小节 = 32 秒） | 整曲或副歌片段，同上两档 |
| 镜头数（经验值） | 每分钟 15–30 个 | 30 秒约 10–20 个 | 每句 1 个"字镜头"，长句 2 个 |
| 平均镜头时长（经验值） | 主歌 2–4 小节一换；副歌 1 小节一换（mv-director `卡点表.md` 节奏套路）。按 100–130 BPM 折算约主歌 4–10 秒、副歌 2 秒左右 | 铺垫 1–2 小节一换并越来越快；副歌每小节一换或一镜内每小节变一次 | 跟句走：一句歌词 = 一镜 |
| 音乐结构对应 | 主歌=交代（母题小、安静）→ 预副歌=憋 → 抽鼓=屏住 → 副歌=兑现 → 桥段=反转 → 最后副歌=最大升级（mv-director `点子.md`） | 只取"铺垫 + 进副歌那一下 + 副歌"，必须包含进副歌的第一拍 | 主歌字少、位置固定；副歌字放大、上屏方式变猛；桥段换版式 |
| 画幅 | 16:9 横屏 1920×1080（B 站、YouTube、用户抖音账号的默认做法都是横版） | 默认 16:9 横版（用户抖音作品的固定做法：横版、画面不加叠字）；用户点名要竖屏再出 9:16 1080×1920 | 同所在档位 |
| 帧率 | 60fps（mv-director 默认，1080p60） | 60fps | 60fps |

注意：用户的抖音做法是"画面里不加叠字、文案进标题和描述"。**歌词算不算叠字要在追问时问清**：歌词视频档歌词就是主体；整曲和卡点短片可以做"无歌词版 + 歌词版"两版。

## 3. 结构模板

### A. 整曲：母题升级型（推荐）

| 段 | 小节（按常见 4/4 流行歌，按实际 song.md 调） | 做什么 |
|---|---|---|
| 前奏 | 4–8 | 世界和主角第一次出现，母题很小；arc 0.2–0.3 |
| 主歌 1 | 8–16 | 逐句演歌词，2–4 小节一换镜，镜内慢推 |
| 预副歌 | 4–8 | 换镜加快、画面收紧变暗；最后一小节蓄力（pre） |
| 抽鼓/断拍 | 0.5–1 | 只留一样东西，定格 ≤1 秒（mv-director 死画面门槛） |
| 副歌 1 | 8–16 | 第一拍大时刻：画面本身变（尺度、世界、母题变形）；每小节一换 |
| 主歌 2 + 副歌 2 | 同上 | 重复歌词不重复画面，母题升级一级 |
| 桥段 | 4–8 | 世界翻面：换角度、反色、换场景一次 |
| 最后副歌 | 8–16 | 全片最大的升级；最后一句回到母题第一次出现的构图（首尾呼应） |
| 尾奏 | 2–4 | 收，慢推或定格 |

### B. 整曲：一镜/连续变形型（适合慢歌、梦境、回忆）

学 Em Cooper《I'm Only Sleeping》（见第 8 节）：不硬切，画面在拍点上**变形**成下一幅；主歌变形慢（2–4 小节一次），副歌变形快（每小节一次）。卡点检查改看"变形关键帧落拍"，不看硬切比例（M1 仍适用，check.py 的"硬切在拍上"项在 plan.md 写明不适用的原因）。

### C. 副歌卡点短片（30–60 秒）

| 段 | 时长 | 做什么 |
|---|---|---|
| 钩子 | 0–1 秒 | 第 0 帧就有主体；从一个强拍或一句歌声进，不从静音和淡入进 |
| 铺垫 | 4–8 小节 | 母题出现并开始失控；镜头 1–2 小节一换、越来越快；最后半小节收（变暗/定格） |
| 进副歌 | 第 1 拍 | 全片最大的一下（M10） |
| 副歌 | 8–16 小节 | 每小节一个动作；hook 句每次出现比上次更猛 |
| 收尾 | 最后 1 小节 | 两种选一：①乐句尾定格；②末帧接回首帧可无缝循环（抖音会自动重播，见 F14） |

### 歌词视频（变体，套在 A 或 C 上）

- **字就是演员**：唱到哪个字，那个字才落下/亮起（M3 逐字 ±3 帧）。同屏只放当前 1 句（最多再留上一句的残影），关键词放大到全句 1.5–2 倍（经验值）。
- **每段换一种上屏语法**：主歌 pop/type，固定位置；副歌 slam/stack/scatter；桥段换版式（竖排、满屏、跟着母题走）。语法名和写法见 mv-director `卡点表.md`。
- **字和画面是一个系统**：学 Raven Kwok《Stickup》（第 8 节）——歌词被解析后驱动生成结构（四叉树按歌词分裂），字从图形里长出来、再碎回图形里，不是"背景 + 底部字幕条"。

## 4. 视觉规范

**卡点规则**（时间一律从 `song.json` 来，cues.json 写 `bar9` / `line3@词`，不手写秒数——mv-director 铁规矩 3）

| 事件 | 落在哪 | 容差 |
|---|---|---|
| 换镜头、段落切换 | 小节线 | 硬切 ±2 帧（M1，评委以此为准）。mv-director check.py 的判定窗更宽（前 1.5 帧到后 0.12 秒，为容许闪白/故障转场晚一两帧落地），只作自检初筛 |
| 进副歌、最后副歌 | 段落第 1 拍 | 必须是大时刻（M10） |
| 关键词兑现 | 该字开唱时刻 | ±3 帧（M3） |
| 拍上脉动 | 每拍 / 底鼓 | 只驱动主体，不只驱动背景；副歌拍点命中最好 ≥50%（mv-director 参考值） |
| 故意的切分 | 拍上（如 bar9.3） | cues.json 写 `"offbeat": true` |

**能量曲线**：在 cues.json 写 `arc`（0..1），主歌 0.2–0.4、预副歌爬升、抽鼓压到 ≤0.2、副歌 0.8–1.0、最后副歌 1.0。成片画面变化量和 arc 的相关 ≥0.4（mv-director）。

**母题**：挑一台"视觉发动机"（字面化 / 尺度升级 / 复制增殖 / 世界翻面 / 物件成角色 / 文字世界 / 镜像重复 / 越界，见 mv-director `点子.md`），每段都在、每段升级。

**人物**：代码画的人不演戏（video-forge 铁规矩 7）。主角用剪影、背影、远景、关节姿态；情绪交给光、天气、尺度和母题。

**字幕/歌词上屏**：上屏比开唱早 ≤0.35 秒、晚 ≤0.15 秒；唱的时候 ≥75% 时间在屏上；字号 ≥100px（1920 宽画布，mv-director check.py；导演守则建议 ≥108px）；不挡主角的脸和关键动作；不进平台遮挡区（G2）。竖屏 1080 宽画布字号按同样的视觉比例换算（≥100px × 1080/1920 ≈ 56px 为下限，经验值，推荐仍用 ≥84px）。

**镜头与转场**：硬切为主，转场正中间 = 卡点时刻；闪白、震动、RGB 分离只是调料，**每次都要有画面本身的变化撑着**（复盘教训：为过卡点检查加脉冲闪动，画面变吵）。闪烁安全按 F12。

## 5. 声音规范

| 项 | 规范 |
|---|---|
| 音乐来源与授权 | 用户提供的歌：需求卡写明授权情况（自己的作品 / 已获授权 / 仅自用不发布）。要发布而没有授权的，告诉用户风险（下架、扣分），不替用户决定。代码作曲（`~/video-forge/tools/music/code_score.py`）生成的配乐可放心发布，用于无现成歌曲的卡点短片 |
| 拍点表 | 用户的歌：mv-director `listen.py` 出的 `song.json`（拍、小节、段落、抽鼓、逐字时间，用 demucs 分轨更准）。代码作曲：`code_score.py --fps 60` 出的 `<名>.beats.json`（字段 `bpm`、`fps`、`sections{intro,build,main,outro}`、`beats[{beat,bar,downbeat,sec,frame}]`）。注意它默认 `--fps 30`，渲 60fps 时必须传 `--fps 60`，否则帧号差一倍 |
| BPM | 以 song.json 测得的为准；网上标的 BPM 只作参考。快歌（≥140 BPM）镜头按 2 小节以上换，避免每拍切到看不清（经验值） |
| 逐字时间 | 必须是强制对齐来的（song.md 写来源），否则歌词只能整句出现，不许逐字卡（mv-director 铁规矩 3） |
| 静默段/抽鼓 | 画面跟着收（M5）：定格、黑场或只留母题，单次 ≤1 秒（mv-director 死画面门槛）；全片任何地方都不能有 >3 秒完全静止（G7） |
| 片段剪辑 | 起点在小节头，终点在乐句唱完后的小节头；首尾各加 ≤20 毫秒淡入淡出防爆音（经验值） |
| 响度 | 发布版积分响度 -14 到 -16 LUFS，真峰值 ≤ -1 dBTP（G4）。原曲母带通常更响，导出时用 `ffmpeg -af loudnorm=I=-14:TP=-1:LRA=11` 再量一遍 |

## 6. 校验逻辑

【美】【工】【量】含义同 `review-standards.md`。"怎么测"里的 check.py / cue_lint.py 都是 mv-director 的脚本。

| 编号 | 检查项 | 必须/加分 | 阈值或判据 | 怎么测 |
|---|---|---|---|---|
| G1/G2/G3/G5/G6/G7 | 通用项 | 按 review-standards | 见原文 | 见原文 |
| G4 | 响度 | 加分 | -14 到 -16 LUFS，TP ≤ -1 dBTP | `ffmpeg -i mv.mp4 -af ebur128=peak=true -f null -` |
| M1 | 主要画面变化落在拍点/小节线 | 必须 | 小节头命中 ≥70%；硬切 ≥80% 落在拍或字上（check.py 初筛）；评委对硬切抽查按 ±2 帧判 | check.py + 切点处连抽 3 帧对 song.json |
| M2 | 每句歌词都有对应画面 | 必须 | cue_lint 0 个 ✗；只看 board 的 `see` 列能猜出歌词大意 | cue_lint.py + 人判 |
| M3 | 歌词逐字对齐 | 必须 | 逐字模式 ±3 帧；整句上屏早 ≤0.35 秒、晚 ≤0.15 秒，唱时在屏 ≥75% | check.py（读 textlog） |
| M4 | 副歌与主歌能量明显不同 | 加分（卡点短片档改必须） | 副歌段每小节平均画面变化 ≥ 主歌段 1.5 倍（经验值） | check.py 运动曲线图 |
| M5 | 抽鼓、静默段画面跟着收 | 加分 | 抽鼓处画面变化低于前一小节 50%（经验值），定格 ≤1 秒 | check.py 运动曲线 + 抽帧 |
| M6 | 贯穿全曲的视觉母题 | 加分（整曲档改必须） | 每段抽 1 帧，每帧都能指出母题 | 抽帧人判 |
| M10 | 进副歌第一拍是大时刻，且是画面本身在变 | 必须 | 画面变化 ≥ 前 0.4 秒的 4 倍或亮度突变 ≥0.12（check.py 大时刻）；-0.2 秒与 +0.05 秒两帧"判若两图"；`what` 写的不是"闪白+震动" | check.py + `stills/审片_大时刻*.jpg` 人判 |
| M11 | 起伏跟计划走 | 加分 | 画面变化与 arc 相关 ≥0.4；无 >1 秒死画面 | check.py |
| M12 | 歌词字够大、不挡戏 | 必须（歌词视频档）/ 加分 | 每句最大字号 ≥100px（1920 宽）；字不压主角脸和关键动作 | check.py 字号 + 逐句图人判 |
| M13 | 盲审：遮住歌词只看画面能讲清故事 | 必须（整曲档） | 评委看遮字幕版，能复述每段发生了什么，和解读卡一致 | 遮字幕版抽帧，美术评委 |
| M14 | 重复歌词/每次副歌在升级 | 加分 | 第 N 次副歌第一拍截图与第 1 次比：尺度、数量、范围至少一项更大；不得原样复用 | 抽帧并排人判 |
| M15 | 片段起止干净（卡点短片档） | 必须（卡点短片档） | 起点离最近小节头 ≤1 帧；终点不切在字中间；第 0 帧有主体 | 对照 song.json + 抽首帧 |
| M16 | 歌词视频：字在"演"歌词 | 必须（歌词视频档） | 每段上屏语法不同；至少 1/3 的关键词有和词义对应的动作（"碎"会碎、"落"会落，经验值） | 逐句图人判 |
| M17 | 不为过检加特效 | 加分 | 全屏闪白/震动次数每分钟 ≤4（经验值）；每个大时刻都有 `what` | 统计 cues.json moments/rules + 抽帧 |
| F12 | 闪烁安全 | 必须 | 任意 1 秒内全屏大幅亮度闪烁 ≤3 次 | 见 `vfx-showcase.md` F12 |

一票否决默认带 G6；用户的歌有授权问题且要发布时，先停下问用户。

## 7. 提示词模板

### 解读卡 / 创意

```
你在为《{歌名}》（{歌手}，{语言}，{BPM} BPM，{时长}）做 MV 的解读卡。档位：{整曲 / 副歌卡点 {起止秒} / 歌词视频}。
材料：歌词 {lrc 路径}；song.md {路径}（段落、抽鼓、大时刻候选）；用户原话：{原话}。
给 3 种解读，每种写：
1. 谁在唱、唱给谁、发生了什么（按歌词顺序，3–5 句大白话）；情绪从 {?} 走到 {?}
2. 主角/物件（剪影能认出的轮廓特征）和 1–3 个场景
3. 视觉发动机（从 mv-director 点子.md 八种里选 1 个主 + 最多 1 个辅）及它在主歌/副歌/桥段/最后副歌各长什么样
4. 进副歌那一下：画面本身怎么变（一句话，没听过歌的人也能想象）
5. 和同类 MV 的差别：不落入"暗底+粒子+歌词条"的默认样子
不许：逐句抓关键词配互不相干的图；让代码画的人物做表情和手部表演。
```

### 分镜

```
按选定解读 {解读编号} 写 cues.json 的 story / board / arc / moments（格式见 mv-director 卡点表.md），再出 6–9 格分镜联系表。
时间只用 song.json 的 bar/line 写法。每句 board 写 says / see / keys（keys 必须是歌词原词）。
段落镜头密度：主歌 2–4 小节一换；预副歌 1–2 小节；抽鼓不切、定格 ≤1 秒；副歌每小节；桥段换世界一次。
大时刻 ≥3 个，进副歌第一拍必有，每个写 what（画面本身怎么变）。
重复的歌词写清"这次比上次升级在哪"。档位是卡点短片时，第 0 帧必须有主体、起点在小节头。
联系表每格：时间（bar/line）| 画面 | 镜头 | 歌词 | 情绪 | arc 值。
```

### 构建 agent 要点

```
你负责把已确认的 cues.json + 风格卡渲成 {1920x1080 / 1080x1920} 60fps 的 MV。
产线：mv-director（铁规矩全部适用：画面只由 t 决定、不用 Math.random/Date、全部代码画）。
骨架文件（只读）：song.json、cues.json、风格卡 {路径}、设定卡 {路径}。不得改时间，只能改画面函数。
每完成一段跑：render.py lines / bars / moments 看图；草稿跑 check.py --draft，✗ 必须改，⚠ 改或在 plan.md 写理由。
不许为过检查加闪白/震动；检查不过先回到画面本身（母题、反差），见 mv-director 审片.md「三轮还过不了」。
交付：out/mv.mp4、check 报告、遮字幕版（盲审用）、NOTES.md（署名与许可）。
```

### 评委关注点

```
美术评委：只按评审标准卡判。先看遮字幕版（M13 盲审、M6 母题、M14 升级、M10 大时刻是不是画面本身在变），再看带字幕版（M12/M16 字是否在演）。
工艺评委：跑 check.py 和 ebur128，逐条给数字（M1/M3/M10/M11/M15/G4/F12）；
  大时刻看 -0.2s 与 +0.05s 两帧；抽鼓处看运动曲线是否下沉。
两位都不评价歌好不好听、音色如何（交给用户）。
```

## 9. 常见坑

1. **逐句配图像幻灯片**：每句一个不相干的场景，或者每个镜头都对回一句歌词、各演各的（《违背的青春》第 1–4 版、第 6–7 版，见 `retros/2026-11-06-weibei-youth-mv.md`）。要一条故事线 + 一个升级的母题。
2. **好看的意象从头到尾不变**，歌词贴在上面：观众说"没有表现歌词"（mv-director `读懂歌词.md`）。
3. **字比唱早半秒以上**：网上 LRC 常差 0.5–1 秒，只用文字和顺序，时间以强制对齐为准。
4. **为过卡点检查加闪白脉冲**：数字过了、画面变吵（《违背的青春》第 1–4 版）。先改画面本身。
5. **主歌太满**：全程 arc 都高，副歌就没有高潮。主歌要收着。
6. **卡点短片从前奏切进去**：前 3 秒没歌声没主体，划走。起点直接放在铺垫的小节头。
7. **beats.json 帧率不一致**：`code_score.py` 默认 30fps，画面 60fps，所有帧号差一倍。传 `--fps 60` 或一律用 `sec` 字段换算。
8. **快歌每拍都切**：节拍器不是 MV；拍子分层（小节头换镜、拍上脉动、字落在唱出时刻）。
9. **人物表演**：代码画的表情和手必僵，用剪影和姿态，情绪交给环境。
10. **没问歌词算不算叠字**：用户抖音习惯是画面不加字，开工前问清，必要时出两版。
11. **故事偏离歌名的主旨**：读懂了歌词、也编成了故事，中心却放在一个配角意象上。《违背的青春》第 8 版写成《纸船靠岸》，用户问："它是违背的青春呐。"故事梗概先单独过用户这一关，再画。
12. **头身两种画法**：豆包画的头配代码拼的身子，评委分数在涨，用户照样说"头是头，身是身"（第 6 版修了四轮）。头和身子要出自同一张画，做法见 `recipes/chalk-pose-mv.md`。
13. **拿骨骼掰大动作**：一张站姿图掰关节，蹲、跪、迈步时肩膀裂开、脚尖乱指。大动作要一个姿势一个姿势地画，骨骼只做小动作。
