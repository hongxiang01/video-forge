# 评审：工艺（v1）

评委角色：工艺评委，按国际动画 / 动态设计奖的工艺标准打分，从严。
审片对象：`renders/ai-howto_v1.mp4`（1920×1080，30fps，228.1s，6842 帧）
检查方法：看了 3 张联系表；在 `review/v1/judge_craft/` 下逐帧抽查了约 80 帧（转场前后、关键词出现的瞬间、连续帧）；用全片逐帧亮度差分找跳变和静止段；用 freezedetect、ebur128、volumedetect 做技术检查；单独测了 `public/assets/ai-howto/music.wav` 和 `audio.wav` 两条音轨的响度。

## 2. 最影响分数的 5 个问题（按严重程度排序）

### ① 转场靠"整屏叠化"，出现双影和残影（全片至少 5 处）
- **位置**
  - 12.3–13.1s（f368–393，SC01→SC02）：传送带、桌腿、钟在两层画面里位置对不上，叠出两套轮廓；新镜头的大钟从上方滑入，压在正在淡出的旧传送带上。
  - 22.3–22.7s（f668–680，SC02→SC03）：九宫格钟表、"不挡 logo"标注、漏斗、机械臂、传送带五层同时半透明，约 12 帧完全看不清。
  - 66.0–66.5s（f1985–1995，SC05→第 2 章标题页）："四条交代方法"淡入时，旧画面的虚线和"?"从标题字中间穿过去。
  - 208.3–208.6s（f6250–6262，SC15→SC16）："定义 / 拦住 / 判断·担责"三个标签和机械臂都出现双影。
  - 212.9s（f6387，SC16→SC17）：变暗的画面与新画面叠在一起，右侧机械臂出现半透明残影。
- **现象**：两个镜头的版式差别很大，却直接做整屏透明度叠化，每次都有 8–15 帧的"双重曝光"。
- **原因推测**：Remotion 里用了通用的 `<TransitionSeries>` fade（或两个 Sequence 的 opacity 交叉），没有考虑两个镜头中的共用元素。风格卡写的是"转场用元素承接"，实际没有做到。
- **怎么改**
  1. 共用元素不参与叠化：传送带、横梁、地面在前后两个镜头里放到同一坐标，只叠化有差别的元素。
  2. 版式差别大的镜头改成"先出后进"：旧元素用 6–8 帧 power2.in 退场，新元素在退场完成后再用 power3.out 入场，两者在时间上不重叠。
  3. 至少把 SC01→SC02 改成真正的元素承接：机械臂抓起那只 10:10 的钟，推近成 SC02 的大钟（缩放 1→3.2，配合位移），不要叠化。
  4. 第 2 章标题页的切入改成干净的硬切，卡在 S17 段末停顿结束的那一帧。

### ② 开头 2.4 秒是空白纸面（f0–73），口播到 2.87s 才开始
- **位置**：0–2.4s 画面只有底部进度条；2.5s 场景才开始淡入；第一句口播从 f86（2.87s）开始。音频前 1.04s 完全无声。
- **现象**：抖音的前 3 秒决定用户会不会划走，本片这 3 秒里既没有画面也没有声音，工艺上是硬伤。
- **原因推测**：时间轴给口播留了 86 帧的前导，画面入场被挂在口播开始之前做"从无到有"。
- **怎么改**：第 0 帧直接给出完整场景（机械臂 + 工单 + 传送带已经在动）；口播前导压到 ≤ 10 帧；或者开头 0.5s 先让一只 10:10 的钟"咔"地落到传送带上，配一下滴答声当钩子。

### ③ 结尾高潮的处理太弱，片尾标题压字
- **位置**：222.0–228.1s（f6622–6842，SC17）
- **现象**
  - S56"指针停在了四点半"是全片的回收点，但那只 4:30 的钟在画面里只有约 70px 宽，没有推镜头，也没有任何强调动作（f6630–6660）。
  - 片尾卡（f6685 起）把"模型决定上限 / 你决定结果"直接叠在约 35% 透明度的旧场景上：旧的"4:30"标签正好位于"模型决定上限"下方、两行字中间，看起来像标题的一部分（见 `judge_craft/z_end.jpg`）；工单上的"给谁看 / 感觉 / 不能错"等字从"你决定结果"和手绘圈后面透出来。
- **原因推测**：结尾直接复用了 S55 的场景，再整体降低透明度当背景，没有为片尾单独构图。
- **怎么改**
  1. S56 期间对那只钟做推镜：1.0→1.6，约 20 帧，power2.inOut，让钟占画面 1/3；指针转到 4:30 的那一帧配一下滴答声，再画一个手绘圈。
  2. 片尾卡出现前，旧场景淡到 ≤ 8%，或者整屏推出画面；"4:30"标签和工单单独先退场。
  3. 两行标题只放在干净的纸面上；手绘圈不要和任何背景文字发生交叠。

### ④ 混音：配乐太响且人声出现时不让位，整体响度偏低
- **数据**
  - 成片整体响度 -18.6 LUFS，LRA 3.4 LU，峰值 -0.4 dBFS。
  - `music.wav` 本身是 -19.9 LUFS，`Film.tsx:60` 里设成 `volume={0.5}`（约 -6dB），折算后约 -26 LUFS；人声轨约 -18.7 LUFS。也就是说，配乐只比人声低约 7dB，而且没有闪避（人声出现时自动压低配乐）。
  - 句间空隙实测：5.0s 处有人声时约 -22dB，11.7s 的句间停顿约 -32.7dB，65.2s 和 171.5s 的章节空隙约 -26dB。章节空隙里配乐的音量已经接近人声。
- **现象**：需求卡要的是"很轻的钢琴 + 时钟滴答当节拍底"，实际配乐的存在感偏强。TTS 语速 +20% 本来就密，配乐再一垫，听感比较拥挤。-18.6 LUFS 比抖音常见的 -14 到 -16 LUFS 低 3–4 dB，用户需要手动调大音量；峰值 -0.4 dBFS 在平台二次转码后有削波风险。
- **怎么改**：配乐 `volume` 从 0.5 降到 0.2–0.25，并做闪避：人声段再压 6dB，句间留 150ms 恢复。成片做响度标准化，目标 -15 LUFS / -1.5 dBTP（`loudnorm=I=-15:TP=-1.5:LRA=7`）。前 1 秒的静音删掉。

### ⑤ 穿插与道具逻辑：遮挡关系说不通，标注指不到东西，强调用反了
- **位置与现象**
  - 209.1s（f6274，SC16）：第 3 根机械臂的夹爪画在钟的前面，夹爪插进了钟的方框里；它和闸门左柱挤在一起，分不清前后关系。
  - 105.5–110s（f3175–3300，SC09）：箭头直接穿过关着的门板；门打开的样子画成一个窄条加一块深色矩形，读起来更像一个盒子，不像门。
  - 117.2s（f3515，SC09）："草稿"标签压在上层传送带的末端轮廓上；上层传送带没有支撑腿，悬在半空。
  - 140.5s（f4276，SC11）："做完了！"气泡的尾巴指向机械臂和文件之间的空白，不知道是谁说的。
  - 210.8–212.9s（f6323–6387，SC16）：整屏压暗成灰褐色，本该被强调的三个人也一起变暗；纸面变脏，违背风格卡"强调只靠橙红和压暗其余"。
  - 全片：底部章节导航的字约 10px，`PDCA` 灰字、出处小字在手机上读不出来。
- **原因推测**：各元素分别定位，没有统一的前后层级（z 轴）规则；压暗用的是覆盖全屏的遮罩，没有排除被强调的对象。
- **怎么改**：给每个镜头定好层级顺序：背景 → 传送带 → 货物 → 机械臂 → 标注 → 人物。夹爪要么抓住钟的顶边（钟画在夹爪的前面），要么停在钟的上方。门的场景里，箭头在门关着时停在门板前，门开了才穿过去。气泡尾巴指向机械臂的夹爪。压暗只作用在背景和机械臂这两层，人物保持全黑，并加橙红描边。所有画面内的文字不小于 24px（1080p 下）。

## 3. 做得好、不要改的地方

- **视觉系统统一且克制**：米色纸底、墨线、只用一种橙红做强调，全片没有跑偏；也没有出现机器人、发光大脑这类俗套。这是本片最值钱的部分。
- **数据和关键词卡点准**：10:10 标注落在"十点十分"上（f324）；+24% 的条形图在 f5492"快两成多"时才开始长出来；-19% 正好落在"慢了差不多两成"上（f5689）；"单向门 / 双向门"标签跟着口播依次出现；"讲意图，不讲步骤"的手绘圈在说完时刚好画完（f2290–2310）；结尾"4:30"标签在"四点半"出现（f6650）。
- **手绘圈 + 字的冲击放大**：一笔画完 1.08 圈、字略放大再回弹，节奏干净，保留。
- **流水线贯穿全片的隐喻做得完整**：钟一直在传送带上；工单从"指针 4:30"一项，到结尾补齐四项并逐项打勾，形成完整回收。S55 工单逐项打勾和口播一一对应，这段是全片最好的一段。
- **传送带持续慢滚做底层运动**：除标题页外，全片没有超过 3 秒的死静止（freezedetect 只在片尾报了 3.0s）。
- **第 2 章四个工位都有专门的道具**：门、防错小碟、闸门、多版本钟，不是只贴字。
- **数据页（SC14）**：条形图、人群图标、秒表的组合信息层级清楚。

## 4. 能不能获奖：2 / 10

理由：风格统一、卡点准，作为抖音知识短片已经达到合格以上；但以国际动画 / 动态设计奖的工艺标准看，动作语言单一（基本靠淡入和叠化）、转场有双影、结尾高潮没有做出来，离入围线还差一个完整的动画打磨周期。
